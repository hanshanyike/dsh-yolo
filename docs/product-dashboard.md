# 助手看板产品规划（看板 2.0）

> 状态：规划稿，待评审 · 2026-08-22 · 触发：快速原型期结束后的第一轮真实使用反馈
> （「看板太简陋了」），需要从「功能有没有」转向「体验好不好」。

## 一、背景

看板目前是五段式静态列表（待办 / 目标 / 里程碑 / 偏好 / 时间线）加三个操作按钮
（✓ 完成 / +1d 推迟 / ✕ 取消）。它证明了数据链路是通的，但作为每天要打开的产品界面，
信息组织、操作深度、反馈闭环都还停留在原型水平。本文档以用户体验为唯一出发点，
规划看板的演进。

## 二、用户与关键时刻

看板的价值不在「打开看板」本身，而在三个具体时刻：

| 时刻 | 用户心里的问题 | 现在的看板回答得了吗 |
|---|---|---|
| **开工时**（早上/切换项目） | 「我现在该关注什么？有什么快到期了？」 | ❌ 要自己扫一遍待办列表心算日期 |
| **被打断后回来** | 「刚才是不是有个提醒我没看到？」 | ❌ 提醒投进哪个会话完全不可见（见 [提醒不可见定位](issue-reminder-visibility.md)） |
| **周期回顾**（周末/汇报前） | 「这周我完成了什么？哪些事还挂着？」 | ❌ 时间线只是一行行摘要，完成数无聚合 |

**核心判断：看板应该是驾驶舱，不是数据库浏览器。** 现在的五个板块是存储结构的直接
投影（按数据类型分），而用户需要的是按「当下与时间」组织的答案。

## 三、痛点清单（按严重度）

| # | 痛点 | 影响 | 严重度 |
|---|---|---|---|
| 1 | **信息架构按数据类型而非时间组织**——最该置顶的「逾期/今日」混在全部待办里 | 开工三秒得不到答案 | P0 |
| 2 | **提醒不可发现**——到期待办与普通待办无视觉区分；已投递的提醒无任何看板侧痕迹 | 提醒蒸发无感知（联动 issue 2） | P0 |
| 3 | **时间线不可点击**——只有一行摘要，detail 与会话归属都不展示 | 「到哪了」的审计价值发挥不出来（联动 issue 1） | P0 |
| 4 | **计划结构是平的**——目标→里程碑→待办的层级存在于数据里（`milestone_title` 关联），看板却平铺 | 看不出一件事的整体进展 | P1 |
| 5 | **操作能力弱**——只能 ✓/✕/+1d；改到任意日期、手动补一条待办都做不到（必须回会话说一句话） | 小操作成本高 | P1 |
| 6 | **无正反馈**——完成后列表里静默消失，没有「今天完成了 N 件」的确认感 | Keep it on track 缺少心理激励 | P1 |
| 7 | **滞留不可见**——`isTodoStale` 已计算 7 天未动，但只渲染成小徽标，没有专区 | 遗忘的事继续遗忘 | P1 |
| 8 | **空状态只讲功能不做引导**——首次打开列了一堆「会记录什么」，没有教用户怎么开始 | 新用户冷启动困惑 | P2 |
| 9 | **偏好区常驻**——低频信息占据一屏位置 | 信息密度错配 | P2 |

## 四、设计原则（从 [VISION](VISION.md) 推导）

1. **打开 3 秒回答「我现在该关注什么」**——时间敏感的置顶，分类学的靠后。
2. **管理，而非代办**——看板让状态一目了然、操作一步到位；任务的录入与理解仍走对话。
   不做成任务编辑器。
3. **私密且内敛**——默认只显示当前工作区；跨工作区聚合是显式开关（路线图「下一步」）。
4. **每个状态变化都留下证据**——操作即事件，时间线是信任的来源。

## 五、分期规划

### V1 · 「今天」视图（P0，本期）

**目标：开工三秒有答案；提醒不再蒸发；时间线可追责。**

1. **今日聚焦区**（置顶聚合，替代「扫列表心算」）：
   - 分三组：`逾期`（红）/ `今日到期`（橙）/ `未来 7 天`（灰），各组带计数徽标；
   - 组内行保留现有 ✓ / +1d / ✕ 快捷操作；
   - 无到期事项时显示「今天没有到期的事 🎉」——正反馈从置顶区开始。
2. **角标分级**：侧边栏 YOLO 按钮角标区分逾期数（红）与到期数（橙）；有「已投递未响应」
   提醒时脉冲高亮（依赖 issue 2 修复的 `reminder_fired` 留痕与响应判定）。
3. **时间线可点击**：事件行展开详情浮层（完整 summary、detail、时间、会话归属徽标）
   ——直接吃掉 [issue 1](issue-timeline-session-attribution.md) 的修复。
4. 原五段式列表保留为下方滚动区（渐进增强，不推翻重来）。

**验收**：造一条逾期、一条今日、一条三天后到期的待办 → 打开看板，置顶区三组各就位、
计数正确；点击时间线任意事件 → 浮层展示详情与归属；完成一条 → 列表消失且置顶区计数即时变化。

### V2 · 计划树与回顾（P1）

**目标：从「待办清单」升级为「有结构的计划」+ 完成感。**

1. **目标详情展开**：点目标行展开其里程碑（进度）与挂在该里程碑下的待办——数据结构
   已就绪（`milestone_title`），只欠交互。
2. **滞留专区**：「7 天未动」的待办单独成组置顶提醒，提供「还做吗？」二选一（继续 →
   顺手改期；不做了 → 取消）。
3. **每日回顾卡**：顶部一行「今日完成 N · 进行中 M · 明日到期 K」，点击展开当日完成清单。
4. **快捷改期与补录**：待办行加「改期」（日期选择器，替代只有 +1d）；顶部加「+ 记一条」
   快速输入（走 POST /yolo/actions 同链路，不走 LLM——快速、零成本）。

**验收**：目标展开树正确分组；滞留组只收 7 天未动的开启待办；回顾卡数字与时间线一致；
改期后到期日即时更新且时间线留痕。

### V3 · 主动型看板（P2，与路线图「下一步」合流）

**目标：看板从「被打开」走向「主动说话」。**

1. **通知中心**：历史提醒流（依赖 `reminder_fired` 事件积累），回答「漏了什么」。
2. **周回顾 digest**：「本周完成 X 件，关闭 Y 个目标，Z 件事滞留超过 14 天」——与提醒型
   对话共用数据。
3. **跨工作区聚合视图**：显式开关，默认关（守住「私密且内敛」）；聚合视图按工作区分组
   显示各自的今日聚焦。

**验收**：通知中心能回放三天内的所有提醒及其响应状态；周回顾数字可从事件表复核。

## 六、明确不做（防范围蔓延）

- **不做任务编辑器**：标题/详情/优先级的表单编辑不做——录入与理解走对话（管理而非代办）。
- **不做甘特图/日历视图**：时间用分组列表表达足够，图表是伪需求。
- **不做多人协作**：个人助手，无分享场景。
- **不做第三方同步**（飞书/日历）：与「零外部服务」立场冲突，永远不做除非愿景变更。

## 七、怎么知道做好了（度量）

| 指标 | 目标 | 采集方式 |
|---|---|---|
| 开工三秒测试：新用户打开看板能否口头答出「现在该关注什么」 | 5 人可用性测试全过 | 人工 |
| 提醒响应时延（投递 → 状态变化） | 中位数 < 10 分钟 | `reminder_fired` 与后续事件的时间差 |
| 看板操作占比（就地操作 vs 回会话操作） | 趋势上升 | 事件表 `session_id` 有无区分 |
