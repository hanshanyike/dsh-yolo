## 一、背景与问题

### 1.1 原型已验证什么

Keeper（M0–M7）与 Organizer（M8）两级已经交付了一个能跑的闭环：LLM 从对话中提取计划项，SQLite/FTS5 长期存储，到期提醒，侧边栏看板展示，用户可以在看板上点掉或推迟任务，也可以在对话里用自然语言处理提醒。175 个测试、CI、npm 包齐备。

自用两周后的真实体验暴露了四个结构性问题：

| # | 问题 | 证据 |
|---|---|---|
| P1 | **提醒打扰工作会话** | 到期提醒通过 `agent.followup()` 注入最近的工作会话，正在写代码时被插入一条「⏰ 提醒」 |
| P2 | **没有自己的对话面** | 想问「我这周干了什么」或随手记一件事，没有自然入口——工作会话里问会污染上下文 |
| P3 | **不知道当天干了什么** | 每天与 AI 的会话有十几个，事后无法回答「今天究竟推进了哪些事、各自到哪了」；AI 帮人完成更多事，但事情的总量超出了人的心智负担 |
| P4 | **看板是静态投影** | 五段式列表按数据类型（todos/goals/milestones/preferences/events）组织而非按时间与当下组织；无筛选、无编辑、无「今日」概念 |

其中 P3 是本次设计最重要的输入：它把根叙事补全了。VISION 说的「跨会话会忘」（意图连续性断裂）是问题的一半——YOLO 帮你**记**；P3 说的「跨会话太多会晕」（全局视野丢失）是另一半——YOLO 帮你**盘点**。产品因此有两个核心答案：**「什么该做了」（提醒与聚焦）** 与 **「今天干了什么」（台账与简报）**。

### 1.2 外部调研的三条启示

- **ChatGPT Tasks 的形态可参照、坑要避开**：独立任务页 + 到点推送 + 点通知回到任务自己的线程查看与回复，这个「任务有自己的投递面」模型与 YOLO 方向一致；其公认缺陷（任务与聊天线程强耦合、删线程毁任务、上下文隔离）反向印证了 YOLO 的设计——计划数据活在 storage 而非任何会话线程里，会话只是投影视图。
- **Copilot UX 准则的「对话优先」要按场景修正**：通用 agent 准则是聊天为主、工作区辅助。但 YOLO 的用户打开面板的第一诉求是**看状态**而非**说话**，因此本次设计把看板放主位、对话做成锚定看板内容的侧栏——这是对通用范式的有意偏离，依据是自用场景的真实诉求排序。
- **Things 的「按当下与时间组织」**：成熟任务管理工具的默认视图都是时间轴（今天/即将）而非数据类型清单，与 P4 的整改方向一致。

## 二、目标用户与关键场景

**目标用户**：本人（重度 deepseek-harness 用户，多项目并行、每天十几个 AI 会话）。产品化（onboarding、默认配置打磨、商店分发）不在本期范围，但数据格式与配置项为未来开放留口子。

四个关键场景（时刻）：

| 时刻 | 场景 | 产品应答 |
|---|---|---|
| 早晨开工 | 打开电脑，想知道今天该关注什么 | 看板默认视图 + 早报通知卡（今日到期、逾期、昨日遗留） |
| 白天工作 | 沉浸在某个工作会话写代码 | 工作会话 100% 静默；到期提醒只在 YOLO 侧边栏角标上出现；随手记事走 YOLO 面板 |
| 收工回顾 | 想知道今天干了什么、还挂着什么 | 晚报通知卡 + 今日台账（事件级 + 会话来源标注） |
| 随时盘点 | 想看全局、改计划、追问细节 | 看板筛选与行内编辑；点「聊一聊」展开侧栏对话，边看边聊、就地生效 |

## 三、产品全景蓝图

### 3.1 产品表面：三件套

```
┌─────────────────────────────────────────────────────────────┐
│  ① 看板（默认面·状态投影）                                     │
│     「什么该做了」+「今天干了什么」                              │
│     筛选 / 今日聚焦 / 任务行 / 台账 / 通知卡                     │
├─────────────────────────────────────────────────────────────┤
│  ② YOLO 会话（一条常驻线程·意图入口）                           │
│     完整助手：查询 / 记录 / 改计划 / 出简报 / 答提醒              │
│     两个视图：对话 Tab（全宽） ⇄ 看板内侧栏（锚定上下文）          │
├─────────────────────────────────────────────────────────────┤
│  ③ 后台记忆引擎（不可见·事实源）                                 │
│     提取（turn 级 LLM）· 存储（SQLite+FTS5+快照）· 召回 · 调度   │
└─────────────────────────────────────────────────────────────┘
        统一交互语法：卡片 → 聊一聊 → 侧栏对话 → 就地生效
```

三个部件的关系：**引擎是唯一事实源**（计划数据在 storage，不在任何会话线程里）；**看板是状态的投影视图**；**会话是意图的入口**。提醒、简报、任务在看板上都是卡片，所有深入交互都是「点卡片 → 聊一聊 → 对话 → 数据更新 → 看板即时刷新」。一条语法走天下。

### 3.2 能力弧线映射

| 愿景弧线 | 版本 | 状态 |
|---|---|---|
| Keeper · 记得 | 0.1（M0–M7） | 已交付 |
| Organizer · 组织 | 0.2（M8） | 已交付（稳定版待发布） |
| **Manager · 盘点** | **0.3（本期）** | **从「被动记录展示」升级为「主动盘点 + 对话管理」** |
| Companion · 陪伴 | 远期 | 蓝图层留口 |

## 四、信息架构与交互设计

### 4.1 布局总览

侧边栏底部保留 YOLO 按钮（唯一常驻入口，兼角标触达点）；点击打开**与常规会话同宽**的 YOLO 面板。面板顶部两个 Tab：

- **看板 Tab（默认）**：全宽看板；右侧可展开「侧栏对话」锚定当前卡片上下文；常态收起；
- **对话 Tab**：YOLO 会话的完整对话视图，与侧栏对话是**同一条线程**的两个视图。

```
┌ 侧边栏 ┐  ┌────────────── YOLO 面板（与常规会话同宽）──────────────┐
│  ...   │  │ [看板 · dsh-yolo]  [对话]                    ─ ✕     │
│  ...   │  ├───────────────────────────────────────────┬─────────┤
│        │  │ 筛选条: [今日][全部][已完成]  [筛选▾]        │ 侧栏对话 │
│ ⬤ YOLO │  │ ☀ 早报卡: 3 件到期·昨日完成 4   [聊一聊]     │ (收起态) │
│ (角标) │  │ 聚焦: 逾期2 · 今日3 · 未来7天5 · 滞留1       │         │
│        │  │ □ 修复看板轮询 bug        [会话·bug修复] 今天 │ 点卡片  │
│        │  │ □ 季度报告初稿           [会话·报告] 逾期1天 │ 的「聊  │
│        │  │ …任务行（行内操作 ✓ ⋯ 编辑）                  │ 一聊」  │
│        │  │ 目标与里程碑（折叠区）                         │ 才展开  │
│        │  │ 今日台账: 6 会话 · 11 件事（带来源徽标）        │         │
│        │  │ [+ 快速记一条…]              [对话开关 ⟨⟩]    │         │
└────────┘  └───────────────────────────────────────────┴─────────┘
```

### 4.2 看板信息架构（自上而下）

1. **筛选条**：预设 Tab（今日 / 全部 / 已完成）+「筛选 ▾」下拉（状态：进行中/逾期/滞留；到期时间；里程碑；关键词）。工作区名只作顶部标识显示，不做切换（跨工作区聚合属 v0.4）。
2. **简报通知卡**：早报/晚报的呈现位（见 4.4），不直接灌进对话流。
3. **今日聚焦**：逾期 / 今日 / 未来 7 天 / 滞留 四个计数胶囊，点击即筛选。
4. **任务区**：按到期组织排序的任务行；每行带**会话来源徽标**（该事项出自哪个会话）、到期状态、快捷操作（✓ 完成 / ⋯ 更多）；行内编辑（见 4.5）。
5. **目标与里程碑**：折叠区（默认收起），进度条 + 状态标签。
6. **今日台账**：当日事件按时间倒序，事件级条目（完成/状态变化/新记录）+ 会话来源徽标；头部一行「N 会话 · M 件事」。「今日」= 本地时区自然日。
7. **快速记一条**：常驻输入框，回车直接入库为待办（默认今日到期），**不经 LLM**——轻操作不烧模型，重表达才进对话。
8. **对话开关**：常驻按钮（不依赖具体卡片），随时可展开侧栏对话。

**偏好不出现在看板**：偏好是给引擎用的记忆（注入 system prompt 生效），不是给人看的台账。看板信息模型收敛为纯计划视角（D14）。

### 4.3 侧栏对话与常驻会话

- **一条常驻线程**：YOLO 只维护一条会话线程，所有卡片的「聊一聊」、对话开关、对话 Tab 打开的是同一条线程，只是锚定的上下文不同（锚定对象随打开入口带入）。
- **锚定语义**：从某张卡片展开时，对话首条上下文是该卡片对应的事项/简报；用户可以追问「昨天的进展呢」「把它改到下周五」，agent 通过既有模型工具（`yolo_action` 等）就地修改，看板即时刷新。
- **能力边界**：完整助手——查询记忆、记录事项、修改计划、生成与解读简报、应答提醒（D6）。
- **生命周期**：YOLO 会话随插件启动创建（`ctx.agents.create()` 已在 M8 调研中验证可行），重启后重建并回放未处理事项。

### 4.4 提醒与简报投递链路

```
到期检测（scheduler 轮询）
   → 投递到 YOLO 会话（followup yolo session）         ← 不再触碰工作会话
   → 面板打开中: 看板通知卡（标题 + 快捷操作）
     面板未打开: 侧边栏按钮角标（未处理计数）
   → 用户处理: 看板快捷操作 / 侧栏对话回复（"已完成""推迟到明天"）
   → storage 状态流转 + 审计事件 → 角标/通知卡清除
```

- **工作会话 100% 静默**（D7）：任何提醒、简报、追问都不注入工作会话，无例外。
- **早晚报**（D12）：可配置时间与开关；早报 = 今日到期 + 逾期 + 昨日遗留 + 目标进展变化；晚报 = 今日完成清单 + 新增记录 + 还挂着的事。呈现为看板顶部通知卡，点「聊一聊」带着简报上下文展开对话，可追问。
- **系统级通知**（面板外推送）本期不做，列为开放问题。

### 4.5 编辑深度

| 对象 | 可编辑字段 | 方式 |
|---|---|---|
| 待办 | 标题、截止日、优先级、里程碑归属、删除 | 行内原地编辑；改期用日期选择；删除需确认并写审计事件 |
| 里程碑 | 标题、状态、删除 | 折叠区内编辑 |
| 目标 | 标题、删除 | 折叠区内编辑 |
| 目标进度 | **不可手动编辑** | 进度只能来自对话陈述或提取（看板改数容易造出「假进度」，违背「管理而非代办」） |

（D15：编辑边界经讨论确认。）

## 五、近期版本需求 · v0.3.0「YOLO 面板 1.0」

范围决策 D17：五项全包。建议节奏：先按发布流程将 Unreleased 的 M7/M8 成果收口为 **0.2.0 stable**，本五项作为 **0.3.0**（alpha → stable）开发，两版本各自主题独立。

### A. 面板重构

**需求**：侧边栏按钮入口 → 全宽 YOLO 面板；看板 Tab 默认 + 侧栏对话可展开 + 对话 Tab；快速记一条输入框。

**要点**：重构 `client/` 的 UI bundle——现侧边栏 drawer（`YoloSidebarDashboard`）升级为面板级视图；侧栏对话为看板 Tab 内的子组件，常态收起、点「聊一聊」或对话开关展开、Esc/点外部收起；快速记一条直写 storage 不经 LLM。

**验收**：按第八节测试场景 TA-1～TA-6 过测，全部通过即验收。

**架构影响**：client bundle 大改；**宿主「与常规会话同宽」面板的承载方式需先行调研**（见开放问题 #1，实现第一风险项）。

### B. 提醒改道

**需求**：提醒由 YOLO 自己投递，工作会话 100% 静默。

**要点**：reminder 插件的投递目标从「最近工作会话 followup」改为「YOLO 常驻会话」；YOLO 会话生命周期管理（启动创建、重启恢复、回放未处理提醒）；侧边栏按钮角标（未处理计数）。

**验收**：按第八节测试场景 TB-1～TB-6 过测，全部通过即验收（TB-1 为核心场景）。

**架构影响**：reminder 插件投递逻辑重写；新增 YOLO 会话管理模块；pending reminder 队列复用。

### C. 今日台账

**需求**：事件级台账 + 会话来源标注。

**要点**：`events` 表补 `session_id` 归属（issue-timeline-session-attribution.md 已定位的缺口，需 schema 迁移）；每个会话维护一句话摘要（turn-end 提取时顺手生成/更新），作为来源徽标文案；台账视图按日聚合渲染。

**验收**：按第八节测试场景 TC-1～TC-6 过测，全部通过即验收。

**架构影响**：schema 迁移（`events.session_id`）；extract 模块增加会话摘要输出；dashboard API 扩展台账数据。

### D. 早晚报

**需求**：定时简报任务，通知卡呈现，可追问。

**要点**：复用 reminder scheduler 基建增加定时任务类型；配置项 `brief.morningTime` / `brief.eveningTime` / 开关（默认开，时间默认 09:00 / 21:00，可关）；简报内容按 4.4 要素生成（一次 LLM 调用）；通知卡支持「聊一聊」锚定简报全文。

**验收**：按第八节测试场景 TD-1～TD-6 过测，全部通过即验收。

**架构影响**：scheduler 扩展；新增简报生成 prompt；LLM 调用建议错峰（沿用既有 off-peak 偏好）。

### E. 看板筛选与编辑

**需求**：预设 Tab + 组合筛选；行内编辑。

**要点**：筛选条件（状态/到期/里程碑/关键词）可独立生效可组合；行内编辑按 4.5 边界实现，全部写审计事件；编辑后 SQLite 与 Markdown 快照同步。

**验收**：按第八节测试场景 TE-1～TE-8 过测，全部通过即验收。

**架构影响**：dashboard API 增加查询参数；actions API 增加 update/delete 动作；前端表格组件重构。

## 七、明确不做与边界

- **不做**目标进度手动编辑（防「假进度」，D15）；
- **不把**偏好放进看板界面（偏好是引擎的记忆，D14）；
- **不做**跨工作区聚合与工作区切换器（v0.4+，M10）；
- **不做**系统级推送通知（面板外触达仅角标；系统通知列开放问题 #2）;
- **不做**多人协作、分享、云端同步（与「本地优先、私密内敛」冲突）;
- **不做**任务管理器级别的复杂功能（甘特图、依赖关系、子任务树）——YOLO 是「管理而非代办」的轨道保持者，不是第二个 Todoist。

## 八、测试场景（v0.3.0 验收标准）

验收以**功能正确**为准，本期不设指标门槛——北极星指标（重复交代 / 错过率 / 托付率）的数据采集延后至有真实使用规模再启用，审计事件已是潜在数据源，无需额外建设。执行方式：以下场景手工过测为主；可自动化部分（schema 迁移、筛选过滤逻辑、台账按日聚合、配置默认值）落入既有 vitest 套件。

### A 面板重构（TA）

| ID | 场景 | 步骤 | 期望 |
|---|---|---|---|
| TA-1 | 打开面板 | 点侧边栏 YOLO 按钮 | 面板以会话同宽打开，默认看板 Tab，筛选条 / 聚焦 / 任务 / 台账完整渲染 |
| TA-2 | Tab 切换 | 看板 ⇄ 对话来回切换多次 | 两视图显示同一条线程的历史，消息不重不漏 |
| TA-3 | 侧栏锚定 | 先点早报卡「聊一聊」，收起后再点某任务行「聊一聊」 | 两次展开的锚定分别为早报 / 该任务；Esc 或 ✕ 收起后可再次展开 |
| TA-4 | 对话开关 | 侧栏收起态点看板「对话」开关 | 侧栏展开，锚定为看板全局 |
| TA-5 | 快速记一条 | 输入「周五取快递」回车 | 任务区出现该待办（今日到期、来源=快速记一条），Markdown 快照同步；无 LLM 提取调用（查提取日志确认） |
| TA-6 | 状态保持 | 做过筛选与编辑后关闭面板再打开 | Tab、筛选条件、侧栏收起态等 UI 状态保持 |

### B 提醒改道（TB）

| ID | 场景 | 步骤 | 期望 |
|---|---|---|---|
| TB-1 | 静默（**核心**） | 造一条 1 分钟后到期的待办，另开一个工作会话等待到期 | 工作会话全程无任何新增消息；提醒只出现在 YOLO 侧 |

| TB-4 | 对话处理提醒 | 从通知卡「聊一聊」回复「推迟到明天」 | 待办改期成功、通知卡消失、审计事件（reminder 处理 / todo 更新）落库 |
| TB-5 | 重启恢复 | 提醒已投递未处理时重启插件 | YOLO 会话重建，未处理提醒回放（通知卡 / 角标仍可见） |
| TB-6 | 并发到期 | 同一调度 tick 内两条待办同时到期 | 各自生成通知卡，计数正确 |
