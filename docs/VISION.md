# YOLO 产品愿景

> **Say it once. Keep it on track.**
>
> 把一次交代变成持续、可信、不过度打扰的跟进。

## 要解决的问题

待办、截止时间和阶段目标经常散落在不同对话里。会话一多，人需要反复回忆：还有什么没做、
哪项安排变了、什么时候应该再看一眼。

YOLO 希望接住这部分连续性。它从对话中整理明确的事项，保存后续变化，并在合适的时间提醒。
用户仍然决定做什么、什么时候做，以及是否授权其他 AI 助手执行。

## 产品边界

YOLO 是管理工作与生活安排的个人助手，不是通用记忆库，也不是无人值守的执行工具。

它会保留：

- 需要持续跟进的待办、目标和里程碑；
- 截止时间、提醒方式和安静时段；
- 完成、推迟、取消、进度变化等与计划有关的记录。

它不会主动收集与跟进无关的偏好、人物画像或通用知识，也不会未经授权修改代码、发送消息或
替用户作出决定。

## 产品形态

YOLO 由助手看板、提醒和上下文对话共同组成：

- **首页**只承接当前确实需要回应的提醒、判断和今日安排，不用普通积压填充；
- **计划**组织今天、接下来、目标和全部开放事项，是长期安排的稳定入口；
- **历史**分开保存已完成、已取消和用户可理解的最近变化，不把内部审计伪装成进展；
- **来源证据**让用户先核对事项来自哪里，再选择是否打开原会话；
- **上下文对话**分为整体助手对话与事项讨论，二者不混用历史，也不与详情或来源预览叠成三栏。

提醒不应插入正在进行的工作会话，也不应抢走用户的输入焦点。主动出现是为了减少遗漏，而不是
制造新的打扰。

## 四个发展阶段

YOLO 的长期方向分为四个阶段：

1. **记得**：从对话中保存真正需要跟进的事项，并能在后续会话中找到。
2. **组织**：把零散事项整理成有状态的计划，记录截止时间、里程碑和变化。
3. **管理**：识别当前最值得关注的事项，在合适的时间提醒，并说明判断依据。
4. **协同**：在明确授权下把工作交给其他 Agent，并把请求、进度、结果与人的决定连接起来。

当前产品已经覆盖「记得」和「组织」的主要能力，并在完善「管理」阶段的优先级判断与提醒体验。
「Agent 任务」属于后续协同阶段，不在当前首版界面中出现，也不代表产品会自动获得执行权限。

## 长期坚持的原则

1. **只记录有管理价值的信息。** 记忆服务于跟进，不以收集更多信息为目标。
2. **用户拥有决定权。** YOLO 可以整理、提醒和解释，不擅自执行或替用户决策。
3. **主动但克制。** 提醒要可感知、可回看、可关闭，同时不打断正在进行的工作。
4. **本地优先。** 计划数据保存在用户的工作区中，不依赖额外的远程存储服务。
5. **变化可追溯。** 完成、推迟和进度更新都应有清晰记录，避免状态悄悄改变。

## 如何判断方向是否正确

我们关注的不是功能数量，而是这些结果：

- 用户重复交代同一事项的次数减少；
- 到期事项和重要约定更少被遗漏；
- 用户能快速理解当前最需要关注什么，以及系统为什么这样判断；
- 提醒带来帮助，而不是打断或焦虑；
- 用户愿意把更多需要持续跟进的事项交给 YOLO 管理。
