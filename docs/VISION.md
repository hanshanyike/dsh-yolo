# YOLO 愿景

> 我们相信，AI 真正缺的从来不是"去做"，而是**记住你要什么，并帮你把承诺兑现到终点**。
> YOLO 打算补齐这一块——做一个不是替你干活、而是帮你把日子沿轨道向前推进的助手。

## 问题本身

我们邀请 AI 参与越来越多的工作：写代码、改文档、做分析。它们很聪明，也很健忘——每次打开会话都是新生，刚说好的目标、定下的截止、承诺过的偏好，关掉窗口就归零。于是人类被迫承担了最不该承担的那份活：**把上下文牢牢攥在自己手里**，一遍遍重复交代。

这不是能力问题，是"连续性"问题。人类之所以会遗忘，是因为我们同时背负太多线索而不可能全记得住；AI 之所以"遗忘"，是因为它天生没有连续性。**执行的稀缺已经被机器解决了，意图的连续性依然无人接管。**我们反复丢的，恰恰是自己说过最想要的东西。

## 我们想成为的那个存在

YOLO 想做的是那个**替你接住线索的存在**。

它静静地生活在你和你的 AI agent 身边：你随口交代的目标、排期、约定、偏好，它都听进去，跨会话、跨上下文地整理成一份你能随时看见、它会替你盯着的计划。然后它做一件人类做烦了的事——**在正确的时候，提醒你该往哪走了**。

它不替你做事，因为它不觉得那样对你更好。它做的是：把"你要什么"这件事，从你的脑海里卸下来，装进一份不会忘、可回看、会提醒的计划里。**你省下来的是注意力，而不是意义感。**你仍然是那个做决定、去行动的人——它只是永远站在你这边，确保你没把重要的事情弄丢。

一句话：

> **Say it once. Keep it on track.**
> 说一遍，它帮你把这件事沿着轨道稳稳推进。

## 产品形态：YOLO 是一个常驻的"超级会话"

承接上面的愿景，这里有一个关键的产品判断：**YOLO 不是贴在你每个工作会话里的补丁——它本身就是一个常驻的"超级会话"。**

- **常驻、且看得懂一切。** 在你其它工作会话之上，始终有一个 YOLO 会话在场：它读得出那些会话里发生了什么，在回合结束把这些沉淀成记忆与信息（目标 / 待办 / 偏好 / 决策），收进自己的私库。
- **提醒即对话，可就地操作。** 到点它来找你，你直接在它这条对话里回复「推迟到明天 / 已完成 / 再提醒一次」，它就地记下。不必中断你手头的工作去别的会话里打岔。
- **每会话注入是可选项，默认关闭。** 我们不做"把所有记忆重新注入每一个会话"——那是高噪声、高成本、很难做准的事。coding agent 需要上下文时，用 `memory_search` / `yolo_query` 工具主动问 YOLO；被动注入只在用户显式开启时发生。

这背后是一条更省力、也更贴近理念的路：**当 YOLO 主动出现时——时机是对的、上下文是完整的、而且是能被回复的。**这三点，恰恰是"往每个会话塞记忆"永远做不好的。

## 一、为什么它必须建立在一层「真实记忆」之上

这一条是 YOLO 的非对称优势，也注定不能取巧。

- **记忆是引擎，不是产品。** 项目经理没有"记忆系统"这个卖点，他卖的是"记得去跟进"。记忆单独存在只是一本日记；只有当记忆能转化为"对此刻的提醒与管理"时，它才从代价变成价值。
- **助手离开记忆，等于每天早上遇见陌生人。** 一个什么都不记得的助手，只会一遍遍问你同样的问题；一个记得你的助手，才知道你现在真正卡在哪。
- 所以我们把两件事绑在一起做：**可持久、可召回**的记忆作为地基（它怎么"知道"），**管理 + 主动提醒**作为地面建筑（它替你"做什么"）。缺了地基，建筑会塌；只有地基，永远是毛坯。

## 二、我们守护的三条立场

无论产品长到多大，这三条不被动摇：

1. **理解，而非关键词。** 它读得懂语义，你说的和它记得的是同一个意思。关键词抓取会制造噪声，也会漏掉所有"说得不标准"的真话——我们坚持用语义去理解你。

2. **管理，而非代办。** YOLO 整理、协调、提醒、对齐；它不替你做决策，不擅自动你的代码、文档、系统。执行权始终在你（或你的 coding agent）手里。**它负责让船不偏航，你负责掌舵。**

3. **私密且内敛。** 数据默认留在本地工作区，零外部服务依赖；不同项目、不同分支的记忆互不混淆，除非你明确要求聚合。信任，是它敢进入你生活的前提。

## 三、能力弧线：它如何一步步成为你身边的人

成长是四级递进：**记得 → 组织 → 预判 → 陪伴**。前两级已经落地：它记得你说的
一切，并把它们整理成有状态的计划。第三级"预判"其实很朴素——**每条记录自带
目标时间，到点就触发**：该提醒时提醒，你回复一句就完成操作；不该出声时它就
安静。最后一级"陪伴"，是理解你的节奏、协同你的 agent——那是远期的事。
这些能力都通过 **YOLO 自己的一方会话**交付，而不是侵入你正在进行的 agent 会话。
详细进度见 [README 路线图](../README.md#路线图)。

## 四、我们明确不做的事

划清边界，避免愿景膨胀成空话：

- **不取代执行力。** 我们不冒充那种"放手不管、自己把活干完"的无人值守 agent；那是另一个物种，也不适合被信任去触碰你的生活。
- **不依赖云端卖隐私。** 不为了"智能"把记忆搬离你的掌控，本地优先是我们的最低限。
- **不变成一个肤浅的聊天框。** 我们做一些聊天气泡做不到的事——长期的、结构化的、会提醒的陪伴，而不是更多的话。

## 五、远景：一个普通工作日的早晨

当路线图走到"陪伴"那一级，希望它长这样：

> 你打开工作区，它已经认识你：知道季度报告是下周的头等大事、知道上次讨论过要在截止前先对齐资源、也知道你上午习惯先处理深度任务。
> 它没有先入为主的絮叨——只是在你开始前，把今天的优先级轻轻摆在你面前，并把一条你三天前提过的、差点被忘掉的约定，放在提醒栏第一行。
> 你不是被 AI 接管了生活，而是**第一次觉得，生活有人替你看管了。**

## 六、我们怎样知道自己走对了

愿景是否在兑现，不看功能数量，看三件事的变化：

- **重复交代变少了** —— 同一件事，你不需要说第二遍。
- **错过变少了** —— 该完成的截止、该兑现的约定，漏掉的次数趋近于零。
- **托付变多了** —— 你开始愿意把越来越多"生活侧"的事交它照看，而不是只有编码任务。

三件事齐头并进的那个方向，就是我们要走的路。
