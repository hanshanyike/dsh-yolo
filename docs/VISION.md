# YOLO 产品愿景

> **交代一次，持续跟进。**
>
> *Say it once. Keep it on track.*
>
> 把一次交代变成持续、可信、不过度打扰的跟进。

首版界面取舍与可点击原型见[助手看板原型与产品设计记录](design/assistant-dashboard-prototype.md)。目标的产品语义和演进路线见[目标管理产品设计](design/goal-management.md)。

## 产品定位

YOLO 是面向工作与生活的个人智能助理。它在用户授权范围内持续理解不同会话，将需要延续的事项、决定、约束和变化维护为可追踪状态，并在合适的时机提醒、协助决策或协调受托 Agent。

当前的计划、提醒、来源和上下文对话是这条路线的第一阶段形态。长期目标不是增加更多独立功能，而是让用户的意图能够跨时间、会话和 Agent 保持连续。

## 要解决的问题

待办、截止时间和阶段目标经常散落在不同对话里。会话一多，人需要反复回忆：还有什么没做、
哪项安排变了、什么时候应该再看一眼。

YOLO 希望接住这部分连续性。它从对话中整理明确的事项，保存后续变化，并在合适的时间提醒。
用户仍然决定做什么、什么时候做，以及是否授权其他 AI 助手执行。

随着工作和生活越来越多地通过 AI 会话完成，用户还会遇到另外三种连续性问题：同一事项在不同会话中不断变化，重要决定和约束难以恢复，以及多个 Agent 的授权、进度和结果无法回到同一个整体安排中。YOLO 的长期方向是补上这层连续性，而不是把所有会话简单拼成一段更长的上下文。

## 产品边界

YOLO 是管理工作与生活安排的个人助手，不是通用记忆库，也不是无人值守的执行工具。

它会保留：

- 需要持续跟进的待办、目标和里程碑；其中目标表示跨一段时间要达成的结果，事项表示最近要做的具体事情，里程碑表示阶段性检查点；
- 截止时间、提醒方式和安静时段；
- 完成、推迟、取消、进度变化等与计划有关的记录；
- 影响后续行动、判断或协作的决定、约束、阻塞和来源证据；
- **长期规划中的 Agent 任务**：明确授权、可追踪、结果需要验收的执行工作。

它不会主动收集与跟进无关的偏好、人物画像或通用知识，也不会未经授权修改代码、发送消息或
替用户作出决定。

## 产品形态

YOLO 由助手看板、提醒和上下文对话共同组成：

- **首页**只承接当前确实需要回应的提醒、判断和今日安排，不用普通积压填充；
- **计划**组织今天、接下来、目标和全部开放事项；目标区域用于观察长期结果、里程碑、下一步和回顾安排，不把目标当成更大的待办；
- **历史**分开保存已完成、已取消和用户可理解的最近变化，不把内部审计伪装成进展；
- **来源证据**让用户先核对事项来自哪里，再选择是否打开原会话；
- **上下文对话**分为整体助手对话与事项讨论，二者不混用历史，也不与详情或来源预览叠成三栏。
- **Agent 任务**在具备独立的任务、授权、结果和验收模型后再进入产品界面；当前版本不把普通 Agent 会话冒充为 Agent 任务。

提醒不应插入正在进行的工作会话，也不应抢走用户的输入焦点。主动出现是为了减少遗漏，而不是
制造新的打扰。

## 四个发展阶段

YOLO 的长期方向分为四个阶段：

1. **记得**：从对话中保存真正需要跟进的事项，并能在后续会话中找到。
2. **组织**：把零散事项整理成有状态的计划，记录截止时间、里程碑和变化。
3. **管理**：识别当前最值得关注的事项，在合适的时间提醒，并说明判断依据。
4. **协同**：在明确授权下把工作交给其他 Agent，并把请求、进度、结果与人的决定连接起来。

当前产品已经覆盖「记得」和「组织」的主要能力，并在完善「管理」阶段的优先级判断与提醒体验。目标目前仍处于从“抽取并记录”走向“可组织、可回顾、可持续推进”的过渡阶段，不能把现有目标卡理解为完整的目标管理器。
「Agent 任务」属于后续协同阶段，不在当前首版界面中出现，也不代表产品会自动获得执行权限。

这四个阶段描述的是用户获得的结果，而不是功能数量。长期目标是成为一层可信的个人协作基础：用户保有目标、权限和最终责任，YOLO 负责持续理解、适时提醒和受控协调，具体执行仍由用户或受托 Agent 完成。

## 长期坚持的原则

1. **只记录有管理价值的信息。** 记忆服务于跟进，不以收集更多信息为目标。
2. **用户拥有决定权。** YOLO 可以整理、提醒和解释，不擅自执行或替用户决策。
3. **主动但克制。** 提醒要可感知、可回看、可关闭，同时不打断正在进行的工作。
4. **本地优先。** 计划数据保存在用户的工作区中，不依赖额外的远程存储服务。
5. **变化可追溯。** 完成、推迟和进度更新都应有清晰记录，避免状态悄悄改变。

## 如何判断方向是否正确

我们关注的不是功能数量，而是这些结果：

- 用户重复交代同一事项的次数减少；
- 到期事项和重要约定更少被遗漏；
- 用户能快速理解当前最需要关注什么，以及系统为什么这样判断；
- 提醒带来帮助，而不是打断或焦虑；
- 用户愿意把更多需要持续跟进的事项交给 YOLO 管理；
- 用户能区分事项、里程碑和目标，并能从目标页面找到下一步与下次回顾；
- 用户在后续会话或 Agent 交接中无需重复说明已经明确的背景。
