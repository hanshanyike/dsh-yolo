## 一、现状审计：为什么值得推倒重来

### 1.1 现状事实（代码级）

| 维度 | 事实 |
|---|---|
| 样式方案 | **零 CSS 文件**。全部视觉规则以 React inline styles 散落在 6 个 TSX 中（`KanbanView.tsx` 693 行最密集） |
| 设计 token | 不存在。`borderRadius: 8`、`1px solid var(--border,#ddd)`、`rgba(47,111,237,0.12)` 等规则以字面量重复出现 |
| 品牌色 | `var(--accent, #2f6fed)`——「任何 IDE 插件」的默认蓝，无辨识度 |
| 图标 | 无图标库。`💬 ✕ ✓ ▸ 🎯 🚩` 等 Emoji/Unicode 充当交互图标，跨平台字形不可控、与宿主风格脱节 |
| 动效 | **零**。无 `transition`、无 `@keyframes`。任务完成、面板开关、通知到达均为硬切 |
| 主题 | 依赖宿主 CSS 变量，但 fallback 值全部写死为亮色（`#fff`/`#111`），宿主不注入即破相；无暗色自有方案 |
| 视觉测试 | 无组件渲染测试（vitest 只覆盖 `tests/*.test.ts` 逻辑层），无视觉回归，无对比度审计 |

### 1.2 六个结构性问题

| # | 问题 | 表现 | 后果 |
|---|---|---|---|
| S1 | **无设计系统** | 同一规则字面量复制粘贴，改一个圆角要摸 6 个文件 | 视觉漂移，维护成本线性上升 |
| S2 | **无品牌辨识度** | 默认蓝 + Emoji 图标，截图放在任何插件里都认不出是 YOLO | 产品无人格，「轨道」叙事在视觉层完全缺席 |
| S3 | **层级扁平** | 通知卡、任务行、目标折叠区、台账视觉权重几乎相同 | 产品最核心的两问（「什么该做了」「今天干了什么」）没有被视觉优先级放大 |
| S4 | **零状态反馈** | 点完成瞬间无确认感；30s 轮询刷新无过渡，内容闪变 | 用户无法确认「我的操作生效了」，对工具缺乏信任 |
| S5 | **质量防线缺失** | 无渲染测试、无视觉回归、无 a11y 审计 | 每次改样式都是盲改，回归不可知 |
| S6 | **主题脆弱** | fallback 写死亮色，暗色 IDE 下变量缺失直接破相 | 一半使用场景（暗色）无质量承诺 |

### 1.3 重设计目标与成功指标

四个维度对应四组可度量目标：

| 维度 | 目标 | 验收指标 |
|---|---|---|
| 视觉风格 | 建立有辨识度的品牌视觉层，5 秒可识别 | 完整双主题 token 表（附录 A）；品牌色脱离宿主默认蓝；对比度全表 ≥ 4.5:1 |
| 布局排版 | 视觉层级与产品信息优先级（两问）对齐 | 七区蓝图落地；密度保持 IDE 级（首屏可见 站牌+信号+≥3 任务行 @ 720px 高） |
| 动效交互 | 每个动效回答「发生了什么」，零装饰性动画 | 8 个命名动画全部有触发语义与 reduced-motion 降级（第六章） |
| 质量保障 | 表达层与逻辑层同等测试水位 | 组件测试 ≥ 24 用例、视觉回归基线 36 张、a11y 审计 0 违规（第八章） |

## 二、设计理念：轨道站厅（Track Hall）

### 2.1 从口号到母题

品牌口号是 *Say it once. Keep it on track.*——「轨道」不只是修辞，它就是产品的心智模型：任务沿时间轨道行进，YOLO 负责让它不脱轨。VISION 里说「它负责让船不偏航，你负责掌舵」，但对外叙事锚点始终是 track。

**重设计的核心决策：把「轨道」从口号升格为界面的视觉母题。** 用户打开面板，看到的不是一个通用任务列表，而是一座「站厅」——他的工作在轨道上运行的调度视图。这是辨识度的来源：隐喻不是贴纸，而是结构本身（轨道=列表脊柱、信号=状态色、线路图=目标、行车记录=台账、广播=简报）。

### 2.2 隐喻映射表

| 产品概念 | 隐喻 | 视觉载体 |
|---|---|---|
| 面板 | 站厅（Track Hall） | 站牌头 + 琥珀信号线 |
| 任务列表 | 轨道（Day Track） | 左侧贯穿的 2px 脊柱 + 节点 |
| 任务状态 | 信号灯（Signal） | 红（逾期）/ 琥珀（今日·进行中）/ 青（未来）/ 紫（滞留）/ 绿（完成） |
| 逾期 | 红色信号 | 信号节点变红 + 行内红字 + 4% 危险色底 |
| 目标与里程碑 | 线路图（Route Map） | 地铁线式水平线路 + 站点 + 行进位置标记 |
| 早报/晚报/到期提醒 | 站台广播（Broadcast） | 左侧广播信号条的通知卡 |
| 今日台账 | 行车记录（Ledger） | 已过站的时刻表式流水 |
| 快速记一条 | 捕获（Capture） | 底部捕获条，回车即「挂上轨道」 |
| 侧栏对话 | 调度通话（Dispatch） | 右侧 dock + 「锚定」上下文条 |
| 空状态 | 轨道空旷 | 脊柱延伸 + 空站节点 + 引导语 |

### 2.3 五条设计原则

1. **轨道先行（Track first）**——一切时间性信息都挂在一根可见的轨道上。脊柱是看板的骨骼，不是装饰。
2. **信号克制（Signal, not noise）**——颜色只承载状态语义；唯一的装饰色是品牌琥珀，且只出现在「品牌时刻」（信号线、行进标记、捕获焦点）。任何时刻屏幕上不超过一种语义红。
3. **密度有礼（Dense but polite）**——保持 IDE 级信息密度（13px 基准、40px 行高），但用编辑级排版纪律（等宽数字、严格 4px 网格、单行省略）换取秩序感。宁可靠齐，不要留白滥用。
4. **动效即反馈（Motion as feedback）**——每个动画必须能回答「刚刚发生了什么」（完成、到达、展开、刷新）。不能回答的动画一律删除。总预算：同屏并发动画 ≤ 2。
5. **主题平等（Theme parity）**——暗色优先设计（ departure-board 气质是品牌的灵魂场景），亮色同步交付，两者共用一套语义 token，禁止「暗色是亮色反色」式的敷衍。

### 2.4 负面清单（明确不做）

- 不引入外部字体（IDE 离线环境 + 体积预算），用系统栈 + 等宽数字达成「时刻表」质感；
- 不引入 framer-motion 等动画库（零运行时依赖，纯 CSS keyframes + transition）；
- 不引入图标 npm 包，自绘 16px 内联 SVG 图标集（1.5px 描边，与描边系统同源）；
- 不做拖拽排序（任务顺序由「逾期>今日>未来>无期」的产品规则决定，拖拽会伪造优先级，违背「管理而非代办」）；
- 不做视差、粒子、3D 等装饰性效果；不做与宿主抢焦点的全局动画；
- 偏好（preferences）继续不出现在看板；目标进度继续只读。

## 三、视觉风格：Token 系统

### 3.1 色彩策略：信号琥珀 + 信号灯语义色

**主品牌色弃用宿主默认蓝 `#2f6fed`，启用「信号琥珀」（Signal Amber）**。依据：

- 语义同源：铁路信号灯的琥珀色 = 「注意，前方有事」——恰好是「今日到期/进行中」的语义；departure board（出发信息板）的琥珀字是数字界面里最具辨识度的「时刻表」符号；
- 与所有主流 IDE 主题（VSCode 蓝、Trae 紫、JetBrains 红）都不撞色，面板在宿主中一眼可辨；
- 明暗两态表现力都强：暗色下琥珀有轻微辉光（board 质感），亮色下加深为高对比文字色。

品牌色不接管全部交互色：**琥珀 = 品牌 + 「当下注意力」语义**，中性墨色承担常规交互（悬停、描边），避免满屏琥珀的廉价感。

### 3.2 完整色板（双主题）

**中性墨阶（Ink）**

| Token | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--y-bg` | `#F7F6F3`（暖纸灰） | `#141416` | 面板画布 |
| `--y-surface` | `#FFFFFF` | `#1C1C1F` | 卡片、站牌、捕获条 |
| `--y-surface-2` | `#EFEDE8` | `#26262B` | 悬停、输入底、次级填充 |
| `--y-line` | `#E4E1D9` | `#2E2E34` | 发丝线、脊柱 |
| `--y-line-strong` | `#C9C5BA` | `#45454D` | 强描边、分割 |
| `--y-text-1` | `#201D17`（暖墨） | `#ECEAE4` | 主文字 |
| `--y-text-2` | `#5C574C` | `#A6A29A` | 次文字 |
| `--y-text-3` | `#6E6A5E` | `#8B877E` | 说明文字（对比度达标版） |

**信号语义色（Signal）**——每个信号给「文字色 / 填充色」两个值，文字色保证 ≥4.5:1：

| 信号 | 语义 | 亮色 text / fill | 暗色 text / fill |
|---|---|---|---|
| `--y-amber`（琥珀） | 今日到期、进行中、品牌时刻 | `#96620D` / `#F0A93C` | `#F2B04E` / `#F2B04E` |
| `--y-danger`（红） | 逾期、删除、错误 | `#C13A2E` / `#E15B4A` | `#F0716B` / `#B5483F` |
| `--y-ok`（绿） | 完成、已达成 | `#2E7D57` / `#4CAF82` | `#66C295` / `#3E7D5F` |
| `--y-future`（青灰） | 未来 7 天 | `#5B6B85` / `#8FA3C4` | `#8FA3C4` / `#5B6B85` |
| `--y-stale`（蒙尘紫） | 滞留 >7 天未动 | `#77688F` / `#A99BC6` | `#A99BC6` / `#77688F` |
| `--y-scrim` | 侧栏对话遮罩 | `rgba(32,29,23,.32)` | `rgba(0,0,0,.48)` |

**品牌专用**：`--y-glow = 0 0 0 1px rgba(amber,.35), 0 0 24px rgba(amber,.18)`（仅用于线路图行进标记与捕获条焦点，全屏同时至多 2 处）。

### 3.3 对比度矩阵（设计目标值，第八章 QA 自动复核）

| 前景 / 背景 | 亮色 | 暗色 |
|---|---|---|
| text-1 / bg | 14.9:1 | 13.6:1 |
| text-2 / surface | 6.4:1 | 6.7:1 |
| text-3 / surface | 5.2:1 | 4.8:1 |
| amber-text / surface | 5.2:1 | 8.3:1 |
| danger / surface | 5.4:1 | 5.4:1 |
| ok / surface | 5.0:1 | 7.3:1 |
| 墨字 / amber-fill 按钮 | 8.4:1 | 8.4:1 |

规则：正文与可交互文字一律 ≥4.5:1；图形与描边 ≥3:1；**禁止**用 fill 色直接当小字文字色。

### 3.4 字体系统

不加载外部字体。质感来自三个系统性手段：**等宽数字、字重对比、字距纪律**。

| 角色 | 规格 | 说明 |
|---|---|---|
| 读数 display | 28px / 32 · w650 · tabular-nums | 站牌计数（逾期 N · 今日 N） |
| 标题 display | 20px / 26 · w650 | 区块大标题（首启引导） |
| 区块 title | 15px / 20 · w600 | 区块标题（日轨分区名等） |
| 正文 body | **13px / 18**（基准） | 任务标题、消息正文 |
| 说明 caption | 11px / 16 · text-2 | 截止日、来源、时间 |
| 微标 micro | 10px / 14 · w600 · letterspacing .04em | 状态徽标，全大写拉丁/中文不加 |
| 时刻 mono | 11–12px · `ui-monospace, SF Mono, Consolas, monospace` | 一切时间、日期、计数 |

字栈：`-apple-system, "Segoe UI", "Microsoft YaHei UI", "PingFang SC", sans-serif`。**所有计数与时间强制 `font-variant-numeric: tabular-nums`**——轮询刷新时数字滚动不跳宽（S4 的排版级解法）。

### 3.5 间距 · 圆角 · 描边 · 投影

- **间距**：4px 基网格。行内元素 gap 4/8；卡片 padding 12/16；区块间 20；面板左右 16（窄）/ 20（宽）。
- **圆角**：`--y-r-sm 6`（chip、小按钮）· `--y-r-md 10`（输入、任务行）· `--y-r-lg 14`（广播卡、线路图卡）· pill 999。
- **描边**：统一 1px `--y-line`；焦点环 2px 琥珀 + 2px offset（`outline`，非 box-shadow，保证 forced-colors 下可见）。
- **投影**（仅四档，暗色加深一档）：
  - e0 无；
  - e1 `0 1px 2px rgba(ink,.06)`——卡片于画布；
  - e2 `0 4px 16px rgba(ink,.10)`——下拉菜单；
  - e3 `0 12px 40px rgba(ink,.18)`——面板本体、侧栏对话。
- **信号线（签名描边）**：站牌头底部 2px 线性渐变 `amber → 40% 处透明`，是面板唯一一处装饰性描边。

### 3.6 图标系统（自绘，16×16）

统一规格：16×16 视窗、1.5px 描边、圆帽圆角、`currentColor`、无填充（状态填充除外）。清单见附录 B，共 15 枚：`check`、`clock`、`plus-day`、`chat`、`dots`、`filter`、`close`、`refresh`、`flag`、`station`、`broadcast`、`plus`、`send`、`chevron`、`source-pin`。

替代现状的 Emoji 图标（`💬 ✕ ✓ 🚩` 全部退役），跨平台渲染一致，且描边宽度与 UI 描边同源。

### 3.7 Token 的工程载体

现状是 inline style，keyframes 无法内联，因此引入**最小样式基建**（仍是零依赖）：

1. `client/design/tokens.ts`——唯一事实源：导出 TS 常量 + CSS 变量名映射；
2. `<YoloGlobalStyle />` 组件——挂载时向 `document.head` 注入一次 `<style id="yolo-design-system">`，内含：`.yolo-scope` 上的全部双主题变量（`[data-y-theme="dark"]` 切换）、全部 `@keyframes`、工具类（`.y-anim-*`）；
3. 面板根节点 `className="yolo-scope"`——所有变量作用域化，**不泄漏到宿主**；
4. 组件内 inline style 只允许引用 `var(--y-*)` 与 tokens 常量，禁止字面量色值（ESLint 防线见 8.5）。

### 4.2 七区逐区规格

**① 站牌头 StationBoard**（52px，surface 底，e0，底部 1px line + 2px 琥珀信号线）

- 右：刷新、关闭图标按钮（28×28，hit 32，hover surface-2 圆角 6）；
- 刷新按钮在轮询进行时图标做 360° 旋转（600ms，linear，仅一次）。

**② 信号带 SignalStrip**（40px，sticky 于站牌头下，bg 带 8% 透明 + backdrop-blur 8px，Chromium 不支持时降级为实色 surface）

### 5.4 RouteMap（线路图 · 签名组件）

把「目标—里程碑—进度」画成地铁线路图，是「Keep it on track」最直接的视觉化：

```
 重构 v0.4 · 发布             68%
 ──●──────◐──────○──────○──▶
  存储层      检索层      面板
  8/30 ✓     进行中      9/20
```

- 每个目标一行，高 56px：目标名（13px w600）+ 进度百分数（mono，琥珀）右对齐；
- **线路**：2px `--y-line-strong` 水平线，x 从 4 到 `calc(100% - 56px)`，末端 ▶ 箭头（行进方向）；
- **站点**（里程碑）：10px 圆，按顺序均布（最小间距 48px）——`done`=绿实心、`active`=琥珀环 + 4px 实心芯、`planned`=空心 line-strong；站名（10px text-3）+ 目标日（mono）置于线下，相邻站点标签上下错位避免重叠；
- **行进标记**：12×16 圆角矩形「车头」骑在线上，位置 = `progress%`，琥珀 fill + `--y-glow`；进度变化时标记沿线路滑动（240ms，ease-out）——**全界面唯一持续存在的琥珀辉光**；
- 多目标纵向堆叠 gap 12 + 发丝分割线；
- 目标名点击 = 原地编辑（标题可改，进度只读——产品红线）；里程碑站点点击 = 高亮 + 浮出改名/状态菜单；
- 4.5 表中「里程碑 chip 点击滚动到站点并高亮」在此落地：站点做 1.2s 琥珀呼吸（两次）。

### 5.5 完成流（含撤销窗口）

```
点节点 → 节点 ping 绿环（300ms）→ 行降透明 45%、截止位换「完成 14:32」
       → 600ms 后行高收起（200ms）→ 底部 micro-toast「已完成 · 撤销」
       → 撤销点击：行原地复活（反向动画）并 POST /yolo/actions 还原
```

撤销窗口 4s。这条链路是「动效即反馈」原则的样板：每一步都在回答「发生了什么」。

## 六、动效交互系统

### 6.1 原则与 Token

- 三问门禁：这个动画回答「什么变了」吗？不回答就删；
- 只动 `opacity / transform`（GPU 合成层），禁止动 width/height/top（例外：行收起用 height，因元素即将卸载）；
- Token：`--y-dur-1 120ms`（hover/press）· `--y-dur-2 180ms`（状态切换、数字 tick）· `--y-dur-3 240ms`（卡片到达、dock）· `--y-dur-4 400ms`（脊柱绘制、面板入场）；
- 缓动：`--y-ease-out cubic-bezier(.2,0,0,1)`（入场）· `--y-ease-in cubic-bezier(.4,0,1,1)`（退场）· `--y-ease-spring cubic-bezier(.34,1.3,.5,1)`（信号 ping）。

### 6.2 命名动画清单（全部 8 个）

| 名称 | 触发 | 规格 | 回答的问题 |
|---|---|---|---|
| `panel-in` | 面板打开 | translateY(8px)+opacity，dur-3，ease-out | 「面板来了」 |
| `spine-draw` | 面板首次挂载 | 脊柱 scaleY 0→1（transform-origin top），dur-4 | 「轨道铺好了」（签名时刻） |
| `card-arrive` | 未处理通知卡渲染 | translateY(12px)+opacity + 广播条琥珀脉冲一次，dur-3 | 「有新广播」 |
| `count-tick` | 信号灯计数变化 | 旧数字 translateY(-8px) 淡出、新数字自下淡入，dur-2 | 「数量变了」 |
| `signal-ping` | 任务完成 | 节点外扩 2→10px 同色环淡出，300ms，ease-spring | 「这件事落定了」 |
| `row-settle` | 完成后 600ms | 高度→0 + opacity→.0，200ms，ease-in | 「它离场了」 |
| `dock-in` | 侧栏对话展开 | translateX(24px)+opacity + scrim 渐显，dur-3 | 「调度上线了」 |
| `route-glide` | 目标进度变化 | 行进标记沿线滑动，dur-3，ease-out | 「它前进到这里」 |

显式禁用清单：无循环动画（route-glow 呼吸仅限被引用高亮的 1.2s 一次性事件）、无 hover 弹跳、无进场瀑布（所有区块同时入场，仅脊柱有先后的绘制感）。

### 6.3 签名时刻

**脊柱绘制**：首次打开面板，琥珀微光的 2px 轨道自上而下铺开（400ms），随后任务行整体 80ms 淡入。这是「站厅开门」的仪式感——每会话只发生一次（重复打开不重播，尊重高频用户）。

### 6.4 reduced-motion 降级

`@media (prefers-reduced-motion: reduce)`：全部动画退化为纯 opacity 切换（≤120ms）；`spine-draw`、`signal-ping`、`route-glide` 直接跳终态；shimmer 骨架改静态。侧边栏按钮的呼吸角标一并停用。

## 七、主题与宿主集成

### 7.1 三层变量架构

```
L1 宿主层   --background / --foreground / --accent …     （宿主注入，可能缺失）
L2 语义层   .yolo-scope { --y-bg / --y-amber / … }        （本文档定义，双主题完整）
L3 组件层   inline style 只消费 var(--y-*)                （禁止越层直取宿主变量）
```

现状问题（fallback 写死亮色）的解法：**L2 不再依赖 L1 的存在性**——YOLO 面板自带完整双主题，宿主变量仅作为暗色判定的信号源之一。

### 7.2 暗色判定策略（挂载时执行一次）

1. 读取宿主 `--background` 计算亮度（`getComputedStyle` + 相对亮度公式），< 0.5 → dark；
2. 宿主变量缺失 → 回退 `matchMedia('(prefers-color-scheme: dark)')`；
3. 结果写入根节点 `data-y-theme="dark|light"`；判定函数带单测（mock 两种环境）。

### 7.3 高对比降级

`@media (forced-colors: active)`：移除全部色底 tint 与投影，改用 1px 实线描边区分层级；信号色交给系统强制色；焦点环保留双描边。`@media (prefers-contrast: more)`：`--y-text-3` 提亮一档、发丝线加深一档。

### 8.4 性能预算

| 项 | 预算 | 手段 |

| 面板挂载到首帧 | < 100ms | 样式注入一次缓存；骨架先行 |
| 30s 轮询重渲染 | 单帧 < 8ms | 分区 `React.memo` + 数据浅比较跳过未变区块；stable key |
| 轮询视觉抖动 | 0 | tabular-nums + 骨架期间不闪内容（S4 的根除） |
| 样式基建体积增量 | ≤ 5KB（gzip 前） | keyframes + 变量 + 15 图标内联，无运行时库 |
| 动画帧率 | 60fps | 仅合成层属性；同屏动画 ≤ 2 |

### 8.5 工程防线

- ESLint：`no-restricted-syntax` 拦截 JSX style 属性中的 `#` 开头色值与 `rgb(`（`tokens.ts` 白名单）；
- tokens 单源脚本在 `npm test` 前置执行；
- harness fixture 与 `src/shared/dashboard.ts` 类型绑定，接口字段变更时编译期报错（防止 mock 漂移）。

## 十、风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| 琥珀与宿主 accent 撞情绪 | 视觉竞争 | 琥珀仅限面板作用域 + 仅品牌时刻；常规交互走中性墨色（3.1） |
| inline style → 变量混排的迁移期样式分裂 | 中途视觉不一致 | 阶段化 PR + 双轨 flag；G2 防线保证新代码不回退 |
| backdrop-blur / color-mix 在旧内核失效 | 信号带破相 | 每处渐进增强都带实色 fallback（4.2②、7.3） |
| 视觉回归在 CI 的稳定性（字体渲染差异） | 误报噪音 | harness 固定字体栈 + 容差 0.1% + 基线按平台分开 |
| 动效在低配机拖帧 | 卡顿感 | 合成层属性 + 同屏 ≤2 动画 + 8.4 预算实测 |
| 「隐喻过重」滑向玩具感 | 专业度受损 | 2.4 负面清单 + 原则 2（信号克制）：隐喻只存在于结构与信号色，不画火车不拟物 |
