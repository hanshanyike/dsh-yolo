# dsh-yolo 校正复盘：管理非代办 · 记忆是引擎不是产品

> 依据用户拍板与项目自有 VISION 校正 **16 号的前提**：
> 本项目**不是通用型记忆**，不该"什么偏好都记"。
> 本文件是**校正版**，替换 16 号里过度倾向"通用记忆"的借调清单。

---

## 0. 前提修正（VISION 原文为据）

- **管理，而非代办。**（`VISION.md` §49）
- **记忆是引擎，不是产品。** 项目经理没有"记忆系统"这个卖点，他卖的是"记得去跟进"；
  记忆单独存在只是一本日记；**只有当记忆能转化为"对此刻的提醒与管理"时，它才从代价变成价值。**（`VISION.md` §39）
- 可持久、可召回的记忆作为地基（它怎么"知道"），管理 + 主动提醒作为地面建筑（它替你"做什么"）。（`VISION.md` §41）

结论：**YOLO 的记忆 = 被跟踪的工作状态 + 影响跟踪行为的操作规则**，不是用户画像、通用偏好、
百科知识、经验教训。

**现有代码已越界**：`src/extract/prompt.ts` 的抽取要求里写——
"preferences: reply language, code style, workflow habits, tool choices, communication style"。
这就是"什么偏好都记"。校正方向：**只保留影响"怎么管"的偏好/规则**（提醒时机、工作时间、可否打扰、
per-project 规则），去掉个人风格/fact/knowledge/lesson 这类通用记忆。

**收窄标准（判断一条该不该记）**：一条"记忆"若**不影响"到点提醒 / 看板管理 / 后续跟踪"**，就不记。

## 1. 校正后的记忆机制范围

| 类别 | 记吗 | 例子 |
|---|---|---|
| **承诺 commitments**（todo） | ✅ | "周三把演示稿发给研发" |
| **计划 plans**（milestone / goal） | ✅ | "9 月上线 v0.4" |
| **操作规则 rules**（影响怎么盯） | ✅ | "提前 1h 提醒"、"工作日 9-18 别打扰"、"该项目每天跟" |
| 用户风格偏好（沟通/代码风格/口味） | ❌ 不记 | "喜欢简洁"、"爱喝咖啡" |
| 通用知识 / 经验教训 / 事实 | ❌ 不记 | "SQLite 更稳"、"学到了 X" |

> 例外：某条事实/教训/规则若**直接改变跟踪行为**才记（例如"这个项目 deadline 会漂移，需每日复核"）。

## 2. 校正后真正值得借的清单（T，只服务"跟踪 + 管理"）

> 每条 = 借什么（出处）→ dsh-yolo 现状（文件）→ 怎么改 → 验收。

### 跟踪质量

**T1 自动抽取承诺的"提案确认"**（dsh-memento proposals / 审批门）
- 现状：`SRC/extract/index.ts` 的 `mergeExtraction` 把 LLM 抽出的 todo/goal/milestone **直接落库**，
  无确认；抽错一个承诺 = 产生一条错误提醒，比不记更糟（信任命门）。
- 改：**自动抽取的关键承诺先进"待确认"，看板可见可审**；日常单条 `auto`（低打扰），
  破坏性/批量（cancel/forget/consolidate）`ask`。拒绝落 `action_denied`（已有）。
- 验收：一条抽错的承诺在确认前不触发提醒；用户可看板一键接受/拒绝。

**T2 承诺溯源：召回带"近期会话历史"证据**（dsh-memento `memory_recall` 两段式）
- 现状：`src/memory/recall.ts` 只搜存下来的行，不读 dsh 历史会话原文；
  提醒到点时模型/用户无从得知"这条承诺当时候怎么说的、上下文的先决条件是什么"。
- 改：`memory_recall`/提醒回填时附"来源会话 + 命中片段"；`recall_log` 记录。
- 验收：提醒"周三交报告"时，能回显当初"还有 X 未定，先确认 Y"的前后文。

**T3 回挖旧会话补漏承诺**（dsh-memory-gate `mine`）
- 现状：只有 turn-end 抽取，**当场没捕捉到的承诺（"别忘了周三交报告"）永远丢了**。
- 改：`/yolo mine`（或轻量定时）扫历史会话，用窄 cue（"别忘了/记住/周三前"）补漏承诺，
  标 `mined` 低置信、进待确认，而不是静默落库。
- 验收：历史会话里出现"别忘了下周交周报"被回挖成一条待确认承诺。

**T4 计划库预算 + consolidate-not-truncate**（dsh-memento 硬预算 + `match`/`consolidate`）
- 现状：`src/storage/schema.sql` todos/prefs 无预算，只增不衰；`applyTodoConsolidate` 只按标题去重。
- 改：给"活跃承诺"设上限，超限**报警让用户 consolidate**，绝不静默丢弃/截断；
  consolidate/remove 用**唯一子串 + 歧义报错**（复用 `deny()`，防误删第一匹）。
- 验收：计划接近上限时看板提示，over-budget 不静默丢承诺；歧义删除报候选清单。

### 提醒纪律（红线工程化）

**T5 投递分级 + 冷却 + 噪声 guard**（dsh-memory-evolve `advisor/delivery.js` +
`advisor/guard.js`）
- 现状：`src/reminder/scheduler.ts` 单强度投递 + `aheadMin`；无 severity、无冷却、无空泛短语抑制。
- 改：due 前温和预告 / 到点提醒 / 逾期升级；`immuneTurns`-式冷却避免刷屏；
  `guard` 归一化+空泛短语（"完成/好的/ok"）+每 tick 一条+去重，防低信息重复提醒。
- 验收：W1–W8——角标不因多卡"一次性全亮"；同一条提醒冷却窗内不二次强发。

**T6 操作规则通道（恒生效特权）**（dsh-memory-gate `capsule`）
- 现状：`working_hours` 有字段但 `scheduler` 不读；无"无论好坏都生效的规则"概念。
- 改：把"工作时别插提醒 / per-project 每日跟"这类硬约束放**特权通道**，不受质量降级影响、恒定注入。
- 验收：关掉/降级语义召回，硬约束仍生效。

### 管理面 / 交互

**T7 反馈只作用于"提醒有无帮助 / 承诺是否仍有效"**（dsh-memory-gate feedback 思路，落到提醒/承诺）
- 现状：`confidence` 只在偏好重复时 +0.1，与"提醒/承诺"无关；提醒从不学习。
- 改：提醒收到"推迟/取消/再提醒"回写 `stale`；承诺被"完成"回写 `good`；某承诺反复"再提醒"→ 降权。
  **不进用户画像**——只调"怎么盯"。
- 验收：反复被"再提醒"的承诺提醒权重下降；被"完成"的承诺不再催。

**T8 `/yolo status` 自诊断 + 降级为"只记录不提醒" + 手动恢复**（dsh-memory-gate `status`/`mode`）
- 现状：语义 degrad 是内部自动、无用户可见面。
- 改：`/yolo status` 显示提醒/抽取健康；持续异常自动降级为"只记录不打扰"，给手动恢复入口。
- 验收：真机——质量下降时 `/yolo status` 提示已降级并可恢复。

**T9 看板即管理面 + 可回复提醒 + 审计 + 4s 撤销**（dsh-memory-evolve 提醒即对话；memento 审计）
- 现状：R1/R6/R7/R17 已实现（通知卡 + 常驻线程 + 审计 + 撤销 + 可回复）。
- 改：**补齐 T1/T3 的"待确认承诺"面**（看板能审、能拒），其余不必大改。

## 3. 明确"不该借 / 应删"（防滑向通用记忆）

| 16 号里的条目 | 是否采纳 | 原因 |
|---|---|---|
| M1 知识/lesson/fact/procedure 分层 | ❌ 删 | 这是通用记忆插件（lite/gate/mneme）的看家本领，**正是 dsh-yolo 差异化之外**；多记=滑向红海（`00-total` 洞察1） |
| M2 全量证据+belief 溯源 | ⚠️ 缩 | 只给"承诺/规则"留证据溯源（T2/T6），不给用户偏好/知识做 belief |
| M4 全量写入质量门 | ⚠️ 缩 | 只做"承诺垃圾闸"（"好的/收到"别成承诺），不给知识打分 |
| M5 全量 TTL/价值分层 | ❌ 删 | 只有承诺/规则需要"是否过期/还是否该盯"；不需要对一堆偏好做价值分层 |

> 保留的"形"：**预算不截断、写前门只防承诺垃圾、受监督写只用于承诺**（对应 T1/T4/T6）。

---

## 4. 结论

1. **把「记忆机制/交互机制」从"通用记忆"收窄到"承诺跟踪 + 非打扰提醒 + 管理看板"**，是校正后的唯一正确范围。
2. **优先级**：T4（计划不丢）+ T2（承诺溯源）+ T5（提醒分级防打扰）先行；T1/T3/T7/T8 随后；T9 大部分已有。
3. **两条红线都不破**：产品红线（管理而非代办、绝不打扰工作会话）与工程红线
   （类型安全 + W1–W8 + 用语真实）；同时**不借"通用记忆广度"**——这本身就是差异化的一部分。
