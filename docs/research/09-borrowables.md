## 一、记忆写入与受监督

| 做法 | 出处 | 怎么落地到 dsh-yolo | 风险/取舍 |
|---|---|---|---|
| P1 **根模型不直接落库**：LLM 只产语义候选/判断，宿主定容量、字节、冲突、幂等、归档顺序 | #01（记忆控制面），#02 佐证 | 把「记忆抽取」委托独立 worker/subagent 产出候选；宿主用确定性校验定优先级、查重、幂等键，再写入 | 多一次 worker 调用/延迟；需保证 worker 不占主会话历史（消耗分级） |
| P2 **独立 worker / subagent 委派**：写入、蒸馏、去重、压缩都走隔离 worker | #01 | 记忆/提醒提炼走专用 worker，宿主只做路由与收据校验 | worker 出错要降级为「宿主兜底收据」，不能卡死主流程 |
| P3 **待确认制（approval/pending）**：写入先进待确认队列，用户认可才生效 | #02（待确认队列）、#08 dsh-memento（approval gate） | 语义抽取结果先进 DSH 的 `*-denied`/待确认通道，看板上可见可审；可在产品上做成「写入默认 auto、破坏性操作 ask」 | 全 ask 会打断用户、增加打扰，与「低打扰」冲突——需分动作分级 |
| P4 **确定性边界剥离**：LLM 出候选，宿主定容量/字节/冲突检测/幂等去重 | #01（核心亮点）、#02 | 明确「哪些判断归宿主代码、哪些交给模型」，并写进单测；容量与字节预算一律宿主算，模型从不数 token | 需为每类判断建立明确划分，前期投入大 |
| P5 **字节预算注入 / 常驻投影**：按 UTF-8 字节预算贪心打包，放不进就跳过单条而非丢整个 section | #08 dsh-memory-lite、#01；#02 佐证 | 记忆/看板快照投影设 `maxBytes`，importance 高的优先装袋，超预算跳过单条 | 预算过低会丢重要信息；需 balance 预算与召回相关度 |

## 二、上下文控制

| 做法 | 出处 | 怎么落地到 dsh-yolo | 风险/取舍 |
|---|---|---|---|
| P6 **语义 + 关键词混合召回**：语义向量 + BM25/关键词双路，补「语义同但措辞异」 | #03 mem0、#01 recall-policy | 中期给「语义插画」加关键词兜底，替代现在单一 FTS5 trigram | 需要维护两套索引，存储/算力成本上升 |
| P7 **recall policy 分级**：召回结果按 keep/drop + tier + reason 逐条评估后再选 | #01（strict/balanced/exhaustive） | 给看板/记忆注入加「召回决策层」，输出 keep/drop 与理由，非法策略自动回退最低档 | 多一层判断逻辑，需校验避免模型乱选 |
| P8 **常驻投影 + 渐进披露**：高频/重要的一直在，低频的摘要注入 + 按需 expand 全文 | #02, #01 | 看板快照常驻（已完成 30s 轮询），记忆低频轨只注入摘要、点击再读全文 | 摘要膨胀要防；expand 需有会话内缓存 |
| P9 **缓存友好快照注入**：快照内容稳定、中途不变，避免撑爆前缀缓存 | #02、#08 dsh-memento（冻结快照） | 看板快照固化到「每会话生成一次」，避免每轮重新拼导致缓存失效 | 快照过旧会与实时状态脱节——需定义刷新时机 |
| P10 **上下文可视化观测**：展示上下文组成/占比/重复/冲突 | #08 dsh-context / dsh-context-doctor（未本地核实，属生态列表线索，落地前需人工确认） | 中期给看板加「记忆打进上下文的构成」角标/调试面 | 纯可观测性，功能收益间接，别过早投入美化 |
| P11 **防模板注入**：记忆内容里的 `{{` 字面量转义，避免被当指令 | #01 | 记忆/提醒回填 system prompt 前做字面量转义 | 小成本，直接可做 |

## 三、召回质量

| 做法 | 出处 | 怎么落地到 dsh-yolo | 风险/取舍 |
|---|---|---|---|
| P12 **召回 = 注入 要分家（门控）**：检索到 ≠ 放上下文，先裁决 use/verify/ignore | #08 dsh-memory-gate（CBDC） | 给看板/记忆召回加判定层，默认只放高置信；全局强偏好走特权通道 | 门控要可解释、可审计，否则是黑盒 |
| P13 **时间有效性 + 自动失效**：事实带 valid_at/invalid_at，过期自动失效 | #05 Zep/Graphiti | 在 SQLite 领域表加时间窗字段，到期自动降权/标失效 | 只做表层面建模，不引整套知识图谱 |
| P14 **证据溯源**：每条记忆/提醒可回溯到出处（会话/条目） | #05、#01（冷引用+sha256）、#08 session-search（未本地核实，属生态列表线索，落地前需人工确认） | 看板卡片/记忆带「来源引用」，可跳转原始会话 | 需保留会话与条目 ID 的映射，占存储 |
| P15 **矛盾自动失效**：新事实与旧事实冲突时，旧的下线 | #05（evidence 判据） | 写入时若命中同主题矛盾，旧条目自动标 supersede/失效 | 需要冲突判定的确定规则，避免误杀 |
| P16 **反馈校准**：用后反馈（helped/harmful）反向更新置信度 | #08 dsh-memory-gate、#02 | 看板完成/放弃动作回写记忆/提醒置信，越用越准 | 收集反馈要零打扰（默认静默）
| P17 **近重复合并**：写入时相似条目自动 supersede 取代关系 | #08 dsh-memory-gate、#01 | 记忆入库做重叠度去重，手动 `consolidate` 全库合并 | 阈值定错会错杀/漏杀，需可撤销 |

## 四、提醒与主动性

| 做法 | 出处 | 怎么落地到 dsh-yolo | 风险/取舍 |
|---|---|---|---|
| P18 **低打扰通知面**：提醒做成「可告警对象的卡片」，绝不打断主会话 | #02（通知卡）、#07 Khoj smart notifications；符合本项目红线 | 保持现状：提醒走侧栏角标 + 看板卡，不注入主会话/不抢焦点 | 低打扰与「及时性」有张力，需分级（due 前预告 vs 到期提醒） |

## 八、进阶记忆治理与注入（10–13 号库新增，强化 P1–P24 的工程落地）

> 这批 dsh 生态库（`10`=dsh-memento `11`=dsh-memory-gate `12`=dsh-memory-lite `13`=dsh-auto-memory）是「最值得深入研究」清单的真机实现，多数条目是对上面既有 P 编号的**工程级强化**，单列以便追踪。

| 做法 | 出处 | 怎么落地到 dsh-yolo | 风险/取舍 |
|---|---|---|---|
| P34 **门下沉到写方法 + approve-what-you-see + `<action>-denied` 审计**：审批门内置 Service 写方法不可绕过；replace/remove 载荷带「旧→新全文」；被拒也落 `<action>-denied` 审计行 | #10（核心），#02 佐证 | 所有看板迁移必经同一中间件（对象化 P3/P25）；完成/撤销的「取消也留痕」入动作审计 | 依赖 UI/人工应答器，无应答器 fail-closed；需配套 |
| P35 **consolidate 显式原子动作**：一次审批 + 单一事务的「条目合并/去重」作为记忆/看板瘦身唯一正规出口，刻意不自动压缩 | #10 | 做「卡片合并/去重」动作，避免隐式 UX 魔法；version 演进史可重建 | 需唯一子串定位 + 候选清单防误合并 |
| P36 **提案式记忆（compaction→proposals→approve）**：压缩摘要截成幂等提案（pending 满弃新），只落提案不写正式记忆，用户审批才落地 | #10 | dsh-yolo「对话语义抽取写记忆」把 LLM 不可靠结果挡在审批门外，看板可见可审 | 需审批入口；全 ask 会打扰（对象化 P3 的分级） |
| P37 **唯一子串定位 + 零/多命中结构化报错**：改/删用「唯一子串 + candidate 清单」，绝不截断/接受歧义 | #10 | 看板「改哪张卡/删哪条」用同语义，避免模糊命中误删 | 中文长句子串易歧义，需良好错误提示 |
| P38 **use/verify/ignore 用后裁决 + reasonCodes 可审计**：belief/risk/新鲜度/词法相关度综合裁决，产出可解释理由码 | #11 | recall 决策层输出 keep/drop+理由（工程化 P12），默认只放高置信 | 需校验避免模型乱选（对象化 P7） |
| P39 **自动降级护栏**：负反馈率阈值 + 最小样本 → 自动降级零注入，红标原因、手动恢复后重评 | #11 | 记忆/提醒质量下降自动降级「只审计不注入」，配合低打扰红线 | 降级后功能静默，需手动恢复入口 |
| P40 **capsule 特权通道承载硬约束**：全局恒稳规则无条件注入、不受弱词法降级 | #11 | 保留用户硬约束（如「工作时别插提醒」）恒生效 | 特权通道要极小、可审计 |
| P41 **文件即真相 + 原子写 + 损坏留好快照**：tmp+rename、mtime 缓存跨进程协调、解析失败留最后好快照不崩溃 | #12 | 持久化层照搬（若记忆用文件而非仅 SQLite 的话）；至少学原子写与损坏降级 | 写侧并发需协调（对象化 P27/P28） |
| P42 **会话开始注入 + digest 去重 + resume 免疫**：agent/pre-step 仅 step1 + 扫 surface 判重 + source 标记 | #12 | 记忆/提醒注入「一次会话一次、续会话不重复」的干净范式 | 与处理器时序对齐；step1 之外需求需额外扩展 |
| P43 **前缀缓存双轨注入**：静态纪律走 systemPrompt.section（字节级锚），动态记忆走 user-role 快照（内容不变不重复注入） | #13 | 看板快照走 section 锚、动态记忆走 context 快照，避免击穿 DeepSeek 前缀缓存 | 快照需定义刷新时机（对象化 P9） |
| P44 **自巩固频控参数化闸门**：minChars 寒暄门槛 / turn 去重 / 冷却（非工作时段翻倍）/ 每日上限 / 失败重试队列 / heartbeat 探活 / 日界跨天重置 | #13、#02 | dsh-yolo「每轮 LLM 语义抽取 + 去重节流」直接复用的成熟模板 | LLM subagent 有 API 成本，需节流预算 |
| P45 **记忆继承用纯路径指针 + 脏内容写闸门**：导入只给路径不整段，写入前过 sanitize/secret/脏 token 闸门 | #13 | 若做「继承他工具记忆」，照搬「指针不整段、写入前过闸门」两条原则 | 指针依赖目标仍存在，需校验路径 |
| P46 **提醒数据面/投递面分层，但缺 due scheduler**：`CALENDAR.md` 数据面 + 首轮注入式弱主动投递面 | #13（对照） | 学「未完成事项注入 next-session 首轮」低打扰冷启动；但**须自己补 due-time scheduler**（15s 心跳触发源 + 到期通知卡 + 看板卡） | 注入式弱主动达不到点；不补 scheduler 就只算"开场提醒" |

## 与 AGENTS.md 铁律的关系与取舍

1. **整理和提醒，不越权执行**：本清单几乎所有条目都以「把该做的事变成可管理、可审计、可撤销的状态」为本旨。P21 明确把「采用主动性的频率控制、拒绝身份伪装和实时打断」定义为必须遵守的红线，**做提醒能力时不得越过此线**。
2. **「绝不打扰工作会话」**：P18（低打扰通知面）是本清单对这条铁律的直接工程化——提醒走侧栏角标 + 看板卡，不注入主会话、不抢焦点。**取舍点在 P19/P20 的「及时 vs 打扰」**：需要分级投递（due 前温和预告 vs 到期更强提醒），并保留「关闭提醒」的硬开关。
3. **`pnpm check` + 单测 + W1–W8 + 用语真实**：本清单的 P30–P33 正是把这三条固化为可执行机制；引入任何借鉴（尤其 P1/P4 受监督写、P6 混合召回）都必须同步补单测并跑 W1–W8，**不能只借机制不付工程债**。
4. **总体取舍提示**：短期优先背靠既有 `applyYoloAction` 动作路径收敛（P1/P3/P5/P19/P23）；对「主动提醒」的全盘借鉴要区分「取频率控制 / 舍身份伪装」；语义能力是记忆质量的软肋，在「LLM 出候选、宿主定正确性」上持续投入，避免语义漏召回/写脏。**进阶条目（P34–P46）中可直接先落的是 P34（门下沉 + 取消留痕）、P35（consolidate）、P42（会话开始注入去重）三件贴着现有动作路径的**；P43/P44 结合「逐轮抽取 + 前缀缓存双轨」在 M9 一并做；P46 的 due scheduler 是提醒差异化核心，值得单独立项。
