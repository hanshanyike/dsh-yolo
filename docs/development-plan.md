# 开发计划

> 本文只记录正在推进和下一批准备推进的工作。已经交付的变化统一记入
> [CHANGELOG](../CHANGELOG.md)，长期方向见[产品路线图](roadmap-ux-priorities.md)。

## 当前批

### 提醒触达闭环

- 保留侧边栏未处理数量，作为持续可见的提醒入口。
- 新提醒到达时显示右下角非模态提示，10 秒后自动消失。
- 提示不抢焦点、不遮挡当前对话；点击后打开助手看板并定位到通知区域。
- 首次载入只建立基线，不补弹历史提醒；同一通知不重复弹出，多条提醒不堆叠。
- 工作会话继续保持静默，提醒只进入 YOLO 自有链路。

### 文档收敛

- 用户入口只保留安装、启动、使用方式和产品边界。
- 开发、测试、架构和维护流程集中到维护者文档，不在 README 中混入内部操作。
- 删除过时原型、阶段性评审和重复计划的公开索引；历史交付以 CHANGELOG 为准。

### 候选版体验收口

- Today“需要关注”行按主理由与其余结构化依据去重展示，窄面板不再复读同一事实。

### 完成标准

- 类型检查、单元测试和构建通过。
- 相关 API/UI E2E 通过。
- 按 [testing.md 第八节](testing.md#八真机端到端验证)完成 W1–W16 中受影响场景的真机走查。
- 用户可感知行为同步到 `README.md`、`docs/usage.md` 或 `docs/product-design.md`。

## 下一批

- **提醒体验继续收敛**：根据真机使用反馈评估提示文案、通知定位后的处理路径和更细的可关闭选项。
- **召回质量评估**：建立可重复的真实措辞样本，验证召回结果是否确实帮助管理承诺、计划和跟进规则。
- **歧义操作保护**：当自然语言修改或删除命中多个事项时，先给出候选让用户确认。
- **长期规则治理**：让可学习的跟进规则保持可检查、可撤销，并避免从一次点击推断长期偏好。

## 不纳入近期范围

- 代替用户执行外部任务或自动操作第三方系统。
- 把一般知识、人物画像或无关偏好收进长期记忆。
- 多人协作、云端同步、甘特图、依赖关系和复杂子任务树。
- 将提醒注入普通工作会话。

## 维护约定

- 产品方向变化先更新[产品路线图](roadmap-ux-priorities.md)，具体批次再更新本文。
- 当前行为以[产品设计](product-design.md)和实现为准；历史版本不复制回开发计划。
- 提交和验证方式见 [CONTRIBUTING](../CONTRIBUTING.md) 与[测试文档](testing.md)。
