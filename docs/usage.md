## 一、安装与启动

> **前置要求**：Node ≥ 22.19，pnpm ≥ 11，以及已安装的 `dsh`（deepseek-harness CLI）。Windows 上请用
> **PowerShell** 运行命令（Git Bash 会破坏 pnpm 的安全删除）。

```bash
git clone https://github.com/hanshanyike/dsh-yolo.git
cd dsh-yolo

pnpm install           # 安装 YOLO 自身依赖（含 better-sqlite3 原生绑定）
pnpm build             # 构建 host 插件 + browser client 到 dist/
pnpm dsh plugin add . --profile web   # 一次性：把本插件按 dsh 标准方式链接进 web profile
pnpm dsh web --no-open --port 4080    # 启动 dsh 宿主 → http://127.0.0.1:4080
```

`dsh plugin add .` 是 dsh 生态的标准安装：插件作为 bundle 挂进 `web` profile（`dsh.bundle.patch`
指向 `cordis.patch.yml`，自动注册全部 host 侧插件行）。`dsh web` 用**已安装的 dsh** 启动，
与宿主环境一致（默认端口 3080；本机被占故开发用 `--port 4080`）。改完代码重跑 `pnpm build`
刷新浏览器即可，无需重启宿主。

启动后打开 **http://127.0.0.1:4080**，选择工作区开始对话即可。YOLO 会自动开始工作：
提到截止时间、设定目标、或说"记住这个"，然后打开左侧边栏底部的 **YOLO 面板** 查看
时间线、任务板与目标进度。

## 二、配置

在 dsh 的 **Settings → Plugins → YOLO** 中可调整全部配置（有默认值，通常无需改动）：

| 分组 | 配置项 | 默认值 | 说明 |
|---|---|---|---|
| 总开关 | 启用 | `true` | 插件总开关 |
| 抽取 | 启用 LLM 提取 | `true` | 每轮对话结束后用大模型语义提取记忆 |
| 抽取 | 模型 | `deepseek-chat` | 提取用的模型名 |
| 抽取 | 最小间隔（秒） | `30` | 同一会话内两次提取的最小间隔（节流） |
| 提醒 | 启用提醒 | `true` | 到期任务自动注入对话 |
| 提醒 | 扫描间隔（秒） | `300` | 后台扫描到期任务的频率 |
| 提醒 | 提前量（分钟） | `0` | 到期前多久提前提醒；`0` = 到点才提醒（默认）。如设 `60` 表示进入到期前 1 小时即提醒 |
| 提醒 | 安静时段启用 | `false` | 开启后，安静时段内到点的提醒先按住、窗口结束后补发 |
| 提醒 | 安静开始 / 结束 | `22:00` / `08:00` | 安静窗口（可跨午夜）；窗口内不打扰 |
| 存储 | 作用域 | `workspace` | 记忆作用域模式 |
| 存储 | 快照节奏 | `daily` | `daily` 每天一次 / `every_10_turns` 每 10 轮一次 Markdown 快照 |
| 召回 | 最大 token | `512` | 动态召回注入 system prompt 的 token 预算 |
| 召回 | 条数 | `5` | 每次召回的最大命中条数 |

> 配置在每轮对话时实时读取，修改后下一轮生效，无需重启。

## 三、核心功能

### 1. 语义提取（自动记忆）

每轮对话结束后，YOLO 用大模型把整轮对话读一遍，结构化提取**管理相关**的记忆——它只记“值得跟进的承诺 / 计划 / 跟踪规则”，不记人物画像、通用知识或生活细节：

- **待办（todos）**：用户承诺的具体任务 + 带时间的**日程承诺**（会议、出行、预约、交付、截止）。
- **目标（goals）**：跨天/跨周想达成的长期目标。
- **里程碑（milestones）**：有目标日期的命名阶段或检查点。
- **跟踪规则（preferences）**：影响“怎么盯、何时提醒”的规则——如提醒提前量、工作时间、per-project 跟进规则。
- **事件（events）**：决策、里程碑达成、带日期的计划等时间线事实。

提取是**去重的**：调用前会把已存记忆压缩成摘要随提示词下发，模型不会重复提取未变化的事实；
写入前还有一道**质量闸门**，确认词（“好的/收到”）与裸元命令（“记住这个”）不会误入库存。
因此重复轮次几乎不产生重复记忆，也不浪费 token。

### 2. 自动召回

- **跟踪规则前置**：已记录的跟踪规则会以 `## User preferences` 形式常驻 system prompt。
- **动态召回**：每次对话根据你的**最新消息**做全文搜索，把相关记忆以 `## Related memory` 注入上下文——不用你说"还记得吗"。

### 3. 主动提醒（可回复）

到期任务会主动变为通知卡（侧栏角标 + 看板卡），并投递到 YOLO 常驻会话。默认“到点才提醒”
（提前量为 0）；你在设置里把“提前量”调大即可获得“到期前 N 分钟提醒”的早期预告。提醒不
打扰你的工作会话。

> 提醒“扫描间隔”在插件启动时读取一次，调整后需重启 dsh 才生效；提前量可即时变更。

提醒是**可回复**的：提醒消息自带待办 id 与操作指引，你直接回复
「已完成 / 推迟到明天 / 再提醒一次」，YOLO 就会就地更新计划，不用去别处操作。

### 4. 有状态的计划

任务不再是一成不变的记录——在任意会话里说"做完了 / 开始做 / 推迟到周五 / 写了一半"，
YOLO 会自动更新对应任务的状态、截止日与目标进度，并在时间线留下审计事件：

- **待办**：`待办 → 进行中 → 已完成/已取消`，可推迟、可再次提醒；
- **目标**：进度 0–100%，达到 100% 自动标记达成；
- **里程碑**：planned / active / done / abandoned 状态流转。

### 5. 记忆持久化

记忆按 **工作区 + git 分支** 隔离（两个项目互不串记忆）。SQLite 是快速存储，
**Markdown 快照是持久记录**——每天（或每 10 轮）生成一份可 diff、可提交到 git 的快照。

## 四、模型可见工具

YOLO 向模型暴露 5 个工具，agent 可以自己读写并推进计划：

| 工具 | 作用 |
|---|---|
| `memory_search` | 全文搜索记忆（CJK 建议用 ≥3 个字符的关键词） |
| `memory_write` | 显式写入 todo / milestone / goal / preference / event |
| `memory_forget` | 软删除记忆（todo→cancelled，milestone→abandoned） |
| `yolo_query` | 查询看板视图：timeline / todos / goals / milestones / preferences |
| `yolo_action` | 就地推进计划：完成/取消/推迟/再提醒待办，更新目标进度，流转里程碑状态 |

> 一般无需手动调用——YOLO 已自动提取。工具主要用于"用户明确要求记住/追踪某件事"、
> agent 需要查看当前记忆时，以及回复提醒时就地兑现操作。

## 五、侧边栏看板

左侧边栏底部有一个 **YOLO 按钮**（🎯），带**待办角标**（未完成待办数量）。点击打开全高抽屉：

- 📋 **待办任务**：按截止时间排序，显示优先级与状态徽章（进行中/逾期/滞留）；未完成待办带
  `✓ 完成` / `+1d` / `✕ 取消` 按钮，点击即就地操作
- 🎯 **进行中目标**：显示进度条与百分比
- 🚩 **里程碑**：显示目标日期与状态
- 💡 **跟踪规则**：key-value 列表（影响怎么盯/何时提醒）
- 🕒 **时间线**：最近的决策、事件与状态流转记录

看板是**全局的**（与具体会话无关），并**自动聚合所有已知工作区**（不再区分工作区，也没有「当前/全部」切换）。
每行都带其所属工作区，操作会路由到对应工作区执行。**打开时只加载一次**，动作或点「↻ 刷新」时才重新拉取
（不在打开时 30 秒轮询）；侧栏角标在关闭看板时仍独立更新。点击外部区域或按 `Esc` 关闭。
看板上的操作与对话里回复提醒走同一条领域动作路径，效果与审计完全一致。

**对话**：看板顶部「对话」打开 YOLO 常驻会话（跨会话有状态，可问"我这周干了什么"）；
每张卡片「聊一聊」则打开一段**全新的锚定对话**（只围绕该卡片，不混入常驻会话历史）。
看板打开时，点击侧边栏其它会话即可切换并自动收起看板；点击今日台帐的来源会话标签，
会先收起看板再跳回该会话。

## 六、数据存储位置

```
<工作区>/.dsh/yolo/
├── yolo-<scopeKey>.db     # SQLite（WAL + FTS5 trigram）——快速存储
└── snapshots/             # Markdown 快照——持久、可 diff 的记录
    ├── 2026-08-22.md      #   每日快照
    └── turn-10-....md     #   every_10_turns 模式的轮次快照
```

- **scopeKey** = `sha1(cwd) 前 12 位` + `/` + `git 分支`（非 git 仓库用 `default`）。
- 换工作区或分支 = 换一套记忆，互不干扰。
- 快照是真相源：DB 可随时从快照重建。

## 七、常见问题

| 问题 | 说明 |
|---|---|
| 看板显示"加载失败" | 插件未加载或服务未启动；确认 `pnpm dsh web` 宿主在运行，且 `pnpm dsh plugin add . --profile web` 做过一次 |
| 看板一直为空 | 完成一轮对话后 YOLO 才会提取；确认配置里"启用 LLM 提取"为开 |
| 提醒没触发 | 检查"启用提醒"与"扫描间隔"；离线期间的提醒会在下次会话开始回放 |
| 回复"已完成"没生效 | 确认回复发生在提醒所在会话；若任务标题与提醒不一致，agent 会按标题模糊匹配，匹配不到会提示 |
| 记忆串到别的项目了 | 记忆按工作区隔离；确认你在正确的目录/分支下工作 |
| 想清空记忆 | 删除对应工作区的 `.dsh/yolo/` 目录（会同时删掉快照） |
| 中文搜索不到 2 字词 | FTS5 trigram 对 ≥3 字符的 CJK 召回最好；2 字查询可能漏，请用更长关键词 |
| 启动报 `SetNamedSecurityInfoW failed (Win32 5)` | Windows 下工作区目录 owner 是 `BUILTIN\Administrators` 时 dsh 沙箱授权失败。以管理员身份运行一次 dsh，或把工作区移到用户目录下 |
| pnpm 报 `[safe-delete] trash operation` | Git Bash 下的坑；请用 **PowerShell** 运行 pnpm |
