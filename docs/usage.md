## 一、安装与启动

YOLO 是 dsh 插件。以下步骤从源码构建插件、加入 dsh 的 `web` profile，并启动 Web UI。

> **前置要求**：系统已安装 Node.js ≥ 22.19 和 pnpm ≥ 11。Windows 请使用
> PowerShell。

```bash
git clone https://github.com/hanshanyike/dsh-yolo.git
cd dsh-yolo

pnpm install
pnpm build
npx @deepseek-ai/dsh plugin add . --profile web
npx @deepseek-ai/dsh web
```

`dsh web` 默认打开 [http://127.0.0.1:3080](http://127.0.0.1:3080)，并尝试在默认浏览器中打开页面。
使用 `--no-open` 可以只启动服务；如果 3080 已被占用，可追加 `--port 4080` 并打开
[http://127.0.0.1:4080](http://127.0.0.1:4080)。

启动后选择工作区并开始对话。YOLO 会在对话结束后整理明确的待办、目标和时间安排；
左侧边栏底部的 **YOLO** 按钮用于打开助手看板。

日常修改代码后，重新运行 `pnpm build` 并刷新浏览器即可。只有插件清单发生变化时，
才需要再次运行 `plugin add`。E2E 和测试数据清理命令见 [testing-e2e.md](testing-e2e.md)。

## 二、配置

在 dsh 的 **Settings → Plugins → YOLO** 中可调整全部配置（有默认值，通常无需改动）：

| 分组 | 配置项 | 默认值 | 说明 |
|---|---|---|---|
| 总开关 | 启用 | `true` | 插件总开关 |
| 抽取 | 启用 LLM 提取 | `true` | 每轮对话结束后用大模型语义提取记忆 |
| 抽取 | 模型 | `deepseek-chat` | 提取用的模型名 |
| 抽取 | 最小间隔（秒） | `30` | 同一会话内两次提取的最小间隔（节流） |
| 提醒 | 启用提醒 | `true` | 到期任务生成通知卡，并最佳努力投递到 YOLO 常驻会话 |
| 提醒 | 扫描间隔（秒） | `300` | 后台扫描到期任务的频率 |
| 提醒 | 提前量（分钟） | `0` | 到期前多久提前提醒；`0` = 到点才提醒（默认）。如设 `60` 表示进入到期前 1 小时即提醒 |
| 提醒 | 安静时段启用 | `false` | 开启后，安静时段内到点的提醒先按住、窗口结束后补发 |
| 提醒 | 安静开始 / 结束 | `22:00` / `08:00` | 安静窗口（可跨午夜）；窗口内不打扰 |
| 存储 | 作用域 | `workspace` | 当前主链路固定使用工作区作用域；user/global 尚未接线 |
| 存储 | 快照节奏 | `daily` | `daily` 每天一次 / `every_10_turns` 每 10 轮一次 Markdown 快照 |
| 召回 | 最大 token | `512` | 已暴露设置；当前动态召回仍使用代码默认值 |
| 召回 | 条数 | `5` | 已暴露设置；当前动态召回仍使用代码默认值 |
| 语义召回 | 启用 / 模型 | `true` / `deepseek-chat` | 用宿主 LLM 异步扩写查询并重排 FTS 候选，失败时回退本地检索 |

> 配置生效时机不同：提取与语义召回按用户消息/轮次读取；提醒提前量、开关和安静时段按 tick
> 读取；扫描间隔需重启插件。`storage.scope` 与 `recall.maxTokens/topK` 当前尚未接入主链路。

## 三、核心功能

### 1. 语义提取（自动记忆）

每轮对话结束后，YOLO 使用大模型识别需要继续跟进的内容。它只保留明确的承诺、计划和提醒规则，不记录人物画像、通用知识或无关闲聊：

- **待办（todos）**：用户承诺的具体任务 + 带时间的**日程承诺**（会议、出行、预约、交付、截止）。
- **目标（goals）**：跨天/跨周想达成的长期目标。
- **里程碑（milestones）**：有目标日期的命名阶段或检查点。
- **跟踪规则（preferences）**：影响“怎么盯、何时提醒”的规则——如提醒提前量、工作时间、per-project 跟进规则。
- **事件（events）**：决策、里程碑达成、带日期的计划等时间线事实。

提取是**去重的**：调用前会把已存记忆压缩成摘要随提示词下发，模型不会重复提取未变化的事实；
写入前还有一道**质量闸门**，确认词（“好的/收到”）与裸元命令（“记住这个”）不会误入库存。
因此重复轮次几乎不产生重复记忆，也不浪费 token。

### 2. 自动召回

- **跟踪规则前置**：已记录的跟踪规则会以 `## User preferences` 形式常驻 system prompt。
- **动态召回**：每次对话根据你的**最新消息**做本地全文搜索；满足门控时还会异步扩写同义/跨语言
  查询并重排候选，失败时回退确定性检索。相关标题以 `## Related memory` 注入上下文——不用你说
  “还记得吗”。

### 3. 主动提醒（可回复）

到期任务会主动变为通知卡（侧栏角标 + 看板卡），并投递到 YOLO 常驻会话。默认“到点才提醒”
（提前量为 0）；你在设置里把“提前量”调大即可获得“到期前 N 分钟提醒”的早期预告。提醒不
打扰你的工作会话。

> 提醒“扫描间隔”在插件启动时读取一次，调整后需重启 dsh 才生效；提前量可即时变更。

提醒是**可回复**的：消息正文只显示任务标题和到期时间，处理规则位于模型的 system section。
你直接回复「已完成 / 推迟到明天 / 再提醒一次」，YOLO 会按标题调用统一动作入口并更新计划。

### 4. 有状态的计划

任务不再是一成不变的记录——在任意会话里说"做完了 / 开始做 / 推迟到周五 / 写了一半"，
YOLO 会自动更新对应任务的状态、截止日与目标进度，并在时间线留下审计事件：

- **待办**：`待办 → 进行中 → 已完成/已取消`，可推迟、可再次提醒；
- **目标**：进度 0–100%，达到 100% 自动标记达成；
- **里程碑**：planned / active / done / abandoned 状态流转。

### 5. 记忆持久化

记忆按 **工作区 + git 分支** 隔离（两个项目互不串记忆）。SQLite 是运行事实源；Markdown
快照是可读、可 diff 的审阅投影，按配置每天或每 10 个真实工作会话轮次生成一次。

## 四、模型可见工具

YOLO 向模型暴露 5 个工具，agent 可以自己读写并推进计划：

| 工具 | 作用 |
|---|---|
| `memory_search` | 全文搜索记忆（CJK 建议用 ≥3 个字符的关键词） |
| `memory_write` | 显式写入 todo / milestone / goal / preference / event |
| `memory_forget` | 软删除记忆（todo→cancelled，milestone/goal→abandoned） |
| `yolo_query` | 查询看板视图：timeline / todos / goals / milestones / preferences |
| `yolo_action` | 就地推进计划：完成/取消/推迟/再提醒待办，更新目标进度，流转里程碑状态 |

> 一般无需手动调用——YOLO 已自动提取。工具主要用于"用户明确要求记住/追踪某件事"、
> agent 需要查看当前记忆时，以及回复提醒时就地兑现操作。

## 五、侧边栏看板

左侧边栏底部有一个 **YOLO 按钮**，角标表示尚未处理的提醒/通知数量。点击后打开助手看板，一级导航只有：

- **今天**：默认页，按“快速记录 → 助手判断 → 需要关注 → 今天 → 今天进展”的顺序展示；
- **即将**：查看未来安排和其他开放事项；
- **已完成**：已完成与已取消分开查看，两类都能重新打开；
- **更多**：刷新看板、切换主题，以及进入“目标与里程碑”“今日台账”等低频页面。

当存在足够证据时，“今天”顶部最多出现一个**助手判断**。它会说明为什么现在需要回应，并给出完成、推迟、讨论等入口；没有合格候选时不会硬凑一张判断卡。同一事项不会同时出现在判断卡和下方列表。第一次看到时展示完整依据，服务端记录已看后再次刷新会收为紧凑状态，仍可展开。

事项行点「处理」进入统一处理面板：先看判断依据与来源，再做完成、推迟、再提醒或“和助手讨论”，也可编辑标题、截止时间、优先级和里程碑。完成后有 4 秒撤销窗口。面板中的“助手将记录的变化”完全来自服务端学习回执；若服务端没有回执，界面不会自行声称“已经学会”。一次操作不会静默改成长期偏好。

看板会**自动聚合所有已知工作区**，没有“当前/全部”切换。每行显示所属工作区，操作按该行 `scope_cwd` 路由到正确工作区，因此聚合行可以直接处理。若部分工作区读取失败，成功数据仍会显示，同时明确提示“部分工作区暂不可用”；此时助手判断不会冒充全局最重要事项。

**加载与刷新**：打开看板只加载一次；完成、推迟等动作或在“更多”中点“刷新看板”才重新拉取。打开时没有 30 秒全量轮询，关闭后角标仍独立轻量更新。点击外部区域或按 `Esc` 可逐级关闭菜单、对话/处理面板和看板。

**两类对话严格隔离**：看板顶部「对话」打开当前工作区的 YOLO 常驻会话（跨打开保留历史，可问“我这周干了什么”）；从助手判断、Today 行或处理面板点“讨论/和助手讨论”，每次都会打开一段**全新的事项锚定对话**，只携带该事项和所属工作区，不混入常驻会话历史。点击今日台账的来源标签会先收起看板，再跳回原工作会话。

## 六、数据存储位置

```
<工作区>/.dsh/yolo/
├── yolo-<scopeKey>.db     # SQLite（WAL + FTS5 trigram）——运行事实源
└── snapshots/             # Markdown 快照——可读、可 diff 的审阅投影
    ├── 2026-08-22.md      #   每日快照
    └── turn-10-....md     #   every_10_turns 模式的轮次快照
```

- **scopeKey** = `sha1(cwd) 前 12 位` + `/` + `git 分支`（非 git 仓库用 `default`）。
- 换工作区或分支 = 换一套记忆，互不干扰。
- 当前没有从快照解析并重建数据库的功能；备份时应以整个 `.dsh/yolo/` 目录为单位。

## 七、常见问题

| 问题 | 说明 |
|---|---|
| 看板显示"加载失败" | 插件未加载或服务未启动；确认 `npx @deepseek-ai/dsh web` 宿主在运行，且 `npx @deepseek-ai/dsh plugin add . --profile web` 做过一次 |
| 看板一直为空 | 完成一轮对话后 YOLO 才会提取；确认配置里"启用 LLM 提取"为开 |
| 提醒没触发 | 检查"启用提醒"与"扫描间隔"；离线期间的提醒会在下次会话开始回放 |
| 回复"已完成"没生效 | 确认回复发生在提醒所在会话；若任务标题与提醒不一致，agent 会按标题模糊匹配，匹配不到会提示 |
| 记忆串到别的项目了 | 记忆按工作区隔离；确认你在正确的目录/分支下工作 |
| 想清空记忆 | 删除对应工作区的 `.dsh/yolo/` 目录（会同时删掉快照） |
| 中文搜索不到 2 字词 | FTS5 trigram 对 ≥3 字符的 CJK 召回最好；2 字查询可能漏，请用更长关键词 |
| 启动报 `SetNamedSecurityInfoW failed (Win32 5)` | Windows 下工作区目录 owner 是 `BUILTIN\Administrators` 时 dsh 沙箱授权失败。以管理员身份运行一次 dsh，或把工作区移到用户目录下 |
| pnpm 报 `[safe-delete] trash operation` | Git Bash 下的坑；请用 **PowerShell** 运行 pnpm |
