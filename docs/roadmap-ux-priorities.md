# 产品路线图

YOLO 的方向是成为一个管理工作与生活的助手：从对话中识别需要持续跟进的内容，整理成可检查的计划，并在合适的时候提醒用户。它负责整理、提醒和追踪，不替用户执行。

历史版本与已交付变化见 [CHANGELOG](../CHANGELOG.md)。本文只保留产品接下来要解决的问题。

## Now

- **让提醒真正被看见**：侧边栏保留未处理数量；新提醒同时出现右下角轻提示，10 秒后自动消失，点击回到助手看板。历史提醒保持静默，多个提示不堆叠。
- **保持看板稳定易用**：继续修复长文字编辑、弹层堆叠、展开与收起、对话刷新等真机使用中暴露的问题。
- **收敛文档入口**：用户文档专注于安装、使用和产品能力；维护者流程与历史材料不再占据用户阅读路径。

## Next

- **更可信的提醒节奏**：让安静时段、再提醒和提醒提前量更容易理解，并基于明确设置工作。
- **更稳妥的自然语言修改**：命中多个事项时先确认对象，避免改错或删错。
- **更可解释的助手判断**：继续改善“为什么现在关注这件事”的证据、来源和反馈闭环。
- **更可验证的长期规则**：用户能看清助手采用了哪些跟进规则，并能撤销不合适的规则。

## Later

- **阶段复盘**：从事件台账中生成可追溯的周度或阶段总结，并允许回到原事项和来源会话。
- **跨工具只读线索**：在不越权执行、不泄露数据的前提下，为计划提供来自其他工具的只读背景。
- **长期陪伴能力**：逐步形成稳定、可控的个人工作节奏建议，但每项主动行为都必须可解释、可关闭。

## 产品边界

- 不成为通用记忆库，只保留会影响提醒、计划或跟进的内容。
- 不替用户完成事项，不静默操作外部系统。
- 不打扰普通工作会话；提醒只使用助手自己的通知与看板入口。
- 本地优先，跨工作区操作必须保持清晰归属。
- 不从一次点击推断长期偏好，也不在没有服务端依据时声称“已经学会”。
