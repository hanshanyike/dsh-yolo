## 参考池
> `docs/research/18-adoption-verdict.md`（借鉴落地结论）· `docs/uiux-real-review.md`（交互评审）·
> `docs/issue-*.md` 已在 v0.3.2 删除（问题已解决）。

**R1. 提醒"到期后用户能看见"（真机链路收口）**
- 效果：你交代"5 分钟后叫我"且切走了，到点后仍能在 YOLO 看板/侧栏角标看到"提醒已发生"，不会"到了却没任何迹象"。
- 意义：这是"说一遍就兜得住"的底座的**信任命门**。提醒"触发了你看不见"，你就不再信任它、不再把事交给它，整件事就没意义。最优先。
- 落点：`src/reminder/*`、`tests/e2e/`
- 验收：在会话 A 交代"5 分钟后到期"，切到会话 B；到期后 ≤5 分钟，在 YOLO 面板/侧栏角标能看到提醒，不依赖用户停留在来源会话。

**R2. 侧栏角标区分"已投递未响应"**
- 效果：角标除了"有几件到期"，还额外标出"提醒发给你了但你还处理"的那几件，更惹眼。
- 意义：光看"到期数"容易被忽略；把"我提醒过、你还没办"单独高亮，是把"别漏办"落到实处，低成本的安心感。
- 落点：`src/ui/dashboard.ts`、`client/sidebar/YoloSidebarDashboard.tsx`
- 验收：角标在"逾期/今日到期"之外，再显示"已投递但未响应"高亮；数据来自 dashboard 新字段。

**R3. 提醒提前量/间隔配置接线 + 语义澄清**
- 效果：你设置的"提前多久提醒、多久扫一次"真正生效；"5 分钟后提醒我"不会变成创建后立刻提醒。
- 意义：现在设置是**死的**（配了无效），且默认提前 60 分钟会让短提醒提前触发，跟直觉不符。修后提醒时机符合预期、误差最小。
- 落点：`src/reminder/index.ts`、`scheduler.ts`、`src/ui/config.ts`、`client/settings/SettingsCard.tsx`
- 验收：设置里 `checkIntervalSec`/`aheadMin` 生效；"5 分钟后提醒我"不会在创建后下一个 tick 提前提醒（提前量按 due 相对计算或文档明示）。

**R4. 提取路径写入会话归属**
- 效果：看板"时间线/今日台账"里，从对话自动提取的"完成/推迟/进度"这类事件能看出是哪个会话发生的。
- 意义：复盘"今天到底哪件事有进展、发生在哪"是"今天干了什么"的核心；归属缺了台账就空洞、无法溯源。这是"盘点"价值的必要组分。
- 落点：`src/extract/index.ts`（`mergeExtraction`）
- 验收：从对话提取的状态变化事件带 `session_id`。

**R5. 看板操作归属诚实标注**
- 效果：你在看板上点的"完成/取消"，时间线上标成"看板操作"而非伪装成某会话；有会话来源的依旧可点跳转。
- 意义：诚实的数据比好看的数据可信，避免"把看板操作误当成某会话的功劳"，也是审计一致性的体现。
- 落点：`src/ui/dashboard.ts`、`client/`
- 验收：无会话上下文的事件显示"看板操作"，不伪装成会话；有归属的事件可点击跳转。

**R6. 完成动作"先写可恢复轨迹"再改状态**
- 效果：误点"完成"能救回（沿用 4 秒撤销）；即便撤销窗口过了，中间迁移也能从审计记录重建，不丢数据。
- 意义：让你敢放心地点"完成"——错了能回退、事后可查证。这是"管理而非代办"的底气（管理允许反悔），不是"执行"。
- 落点：`src/shared/actions.ts`、`src/storage/repository.ts`
- 验收：完成/归档可撤销；撤销不丢数据，状态可从审计事件重建。

**R7. 提醒正文与 agent 指令分离（收口）**
- 效果：你看到的是干净人话"⏰ 提醒：周二开会"，不会有"请用 yolo_action 工具…"这类给模型的指令混进来。
- 意义：提醒是给你看的，不是给模型看的；把路由指令挪到 system 段，观感干净、也便于维护。目前基本已做，此为收口。
- 落点：`src/memory/recall.ts`（yolo-instructions）、`src/reminder/scheduler.ts`
- 验收：聊天里只出现人类可读的 ⏰ 提醒文案，路由指令放 system 段。

**R8. 记忆诊断 + 一键去重**
- 效果：后端继续提供召回/抽取质量和重复候选，并可用 `consolidate` 显式合并；v0.3.3 助手看板不再展示“记忆健康”折叠区。
- 意义：保留可诊断和瘦身能力，但不让引擎指标抢占“今天该回应什么”的主任务。
- 落点：`src/ui/dashboard.ts`（health）、`src/storage/`、统一 actions。
- 验收：诊断数据与显式合并路径可用；主看板不出现“记忆健康”模块。

**R9. 今日唯一判断 + 支持列表**
- 效果：看板最多突出一个有证据的助手判断，其余事项进入“需要关注/今天”；主判断不在列表重复。
- 意义：避免打开几十条后仍由用户自己排序，同时不把确定性不足的事项强行包装成 AI 结论。
- 落点：`src/attention/`、`src/ui/dashboard.ts`、`client/panel/v2/`。
- 验收：候选不足时无判断卡；候选存在时最多一个，原因与 evidence 一致且排序刷新稳定。

**R10. 简报（早/晚报）频率与关闭**
- 效果：早上/傍晚各一条"今天该干什么/干了什么"的通知卡；频率可限、设置里能关。
- 意义：把"今天"主动推给你，是"主动盘点"的体现；但主动推送怕烦人，所以要有频率上限和关闭开关，把打扰控制权交给你。
- 落点：`src/reminder/index.ts`、`brief.ts`、`client/settings/`
- 验收：每日本地一次；设置可关闭；有频率上限。

**R11. 看板"快速记一条"**
- 效果：看板底部常驻输入框，敲一句回车就成一条"今日到期"待办，不经过模型。
- 意义：随手记的最短路径。轻操作不烧 token、不用等 AI，做到"想到就记、不打断"。是"记下来"的零摩擦入口。
- 落点：`client/panel/KanbanView.tsx`（capture）、`src/ui/actions.ts`
- 验收：回车直接入库为"今日到期"待办，不经 LLM；有即时反馈。

**R12. 事项处理面板 / 筛选 / 空态**
- 效果：不用离开看板就能先看依据，再完成、推迟、讨论或编辑截止时间/优先级/里程碑；筛选和各视图空态保留。
- 意义：把看板从"只读投影"变成"可操作的工作面"——计划的增删改都在这里完成，空态不让人懵。是"管理而非代办"的落地形态。
- 落点：`client/panel/v2/TaskActionPanel.tsx`、`src/ui/actions.ts`。
- 验收：处理面板先依据和快速动作、后编辑与危险操作；动作返回服务端回执；筛选和空态文案合理。

**R13. 真·语义召回**
- 效果：你用"季度总结"也能翻出之前记的"Q3 report"（跨语言/换说法）——不用记得原话。
- 意义：记忆只有"找得到"才有用；语义召回解决"同义不同词"，把"说一遍就记住"提升到"换个说法也找得到"。
- 注意：有兜底——LLM 失败自动回退确定性搜索，风险可控；这是最核心的"智商点"之一。
- 落点：`src/memory/semantic.ts`、`recall.ts`、`index.ts`
- 验收：搜「季度总结」命中 `Q3 report`；LLM 扩写/重排带确定性兜底 + 每日预算；失败回退确定性 FTS，不静默置空；写入 `recall_log`。

**R14. 时间有效性 + 自动失效 + 证据溯源**
- 效果：过去定的事实（如"端口 8080"）后来变了/过期了，旧的自动失效、不再乱注入；每条都能看到是哪条会话/条目来的。
- 意义：防止"过时记忆误导你"。时间感知 + 可溯源是"记忆可信"的关键，比"记更多"更重要；只做表层面，不引大图谱，务实。
- 落点：`src/storage/schema.sql`、`repository.ts`、`recall`
- 验收：事实带 `valid_at`/`invalid_at`，到点自动失效/降权；每条可回溯到产生它的会话/条目。

**R15. use/verify/ignore 用后裁决 + 置信回写 + 自动降级**
- 效果：你用过某条记忆后（有帮助/没帮助）系统静默记下；如果某类记忆经常没用，系统会自动"少用它/不再主动喂"，并给你恢复入口。
- 意义：让记忆"越用越准"，且坏记忆不伤你；零打扰（默认静默收集），是质量的自适应护栏。
- 注意（有权衡）：需要反馈信号与样本量，别误伤；属"质量治理"，不必急着上。
- 落点：`src/memory/recall.ts`（policy）、`src/memory/tools.ts`
- 验收：用后反馈（helped/harmful）静默回写置信；质量下降（负反馈率阈值+最小样本）自动切到"只审计不注入"，给手动恢复入口。

**R16. 前缀缓存双轨注入**
- 效果：每次会话重复注入的"静态规则"和"动态记忆"分开、内容稳定，不把大模型的下文缓存打爆。
- 意义：省钱省时。大模型按 token 计费、前缀缓存命中会大幅降本提速；把注入写稳定，同会话多次调用不重复计费、更快。是"长期陪着"的隐形工程。
- 落点：`src/memory/recall.ts`、`index.ts`
- 验收：静态纪律走 `systemPrompt.section` 锚、动态记忆走 context 快照；同一会话多次装配内容稳定，不击穿缓存。

**R17. YOLO 自己的一方"超级会话"**
- 效果：提醒/计划管理发生在 YOLO 自己那条常驻会话里；你在里面回"推迟/完成"就生效，不占用也不打扰你的工作会话。
- 意义：这是愿景的核心形态——"提醒即对话、可就地操作"，让 YOLO 从"工具"变成"常驻伙伴"。
- 注意：这条最"大"、最接近产品灵魂，建议在基础闭环稳定后再立项。
- 落点：`src/reminder/`、`src/ui/session.ts`、`client/panel/ChatPane.tsx`
- 验收：提醒/计划管理收敛进 YOLO 常驻线程；用户在 YOLO 会话回复"推迟/完成"即生效，不借用工作会话。
